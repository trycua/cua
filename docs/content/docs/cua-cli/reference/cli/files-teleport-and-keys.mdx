Import a signed-in session (cookies, or a single-app session like Slack's) into the Keyvault, without delivering it anywhere. A later `cua teleport push --sandbox NAME` (or the review sheet's "Save to Keyvault") can deliver it; it stays sealed until then. The daemon asks for Touch ID or your login password.

```text output
cua keyvault import-session [OPTIONS] --app <APP>
```

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| <span id="cua-keyvault-import-session--app"></span>`--app` | string | required | The app to import from (a teleport provider id: `chrome`, `firefox`, `slack`, ...; `cua teleport providers` lists every one on this computer). |
| <span id="cua-keyvault-import-session--profile"></span>`--profile` | string |  | The browser profile (name or path); default: the default profile. Ignored for a single-app provider (Slack, Discord, ...). |
| <span id="cua-keyvault-import-session--site"></span>`--site` | string |  | Only this site's cookies (a registrable domain such as github.com). Repeatable; a browser with none named imports every site's cookies. Ignored (the whole session is one item) for a single-app provider. |
| <span id="cua-keyvault-import-session--include-storage"></span>`--include-storage` | boolean | `false` | Also carry each named site's localStorage / IndexedDB origins. |
| <span id="cua-keyvault-import-session--include-passwords"></span>`--include-passwords` | boolean | `false` | Also carry each named site's saved passwords, as part of this same session item (`cua keyvault import-passwords` keeps them as their own items instead, one per site). |
| <span id="cua-keyvault-import-session--session-only"></span>`--session-only` | boolean | `false` | Only session cookies: drop every persistent cookie. |
| <span id="cua-keyvault-import-session--drop-long-lived"></span>`--drop-long-lived` | boolean | `false` | Drop persistent cookies that expire more than 30 days out (long-lived refresh tokens), keeping short sessions. |

**Examples**

```bash test="cli-shape" id="ref-cua-keyvault-import-session"
cua keyvault import-session --app chrome
cua keyvault import-session --app chrome --site github.com --site example.com
cua keyvault import-session --app firefox --profile "Profile 1"
cua keyvault import-session --app slack
```

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Success. |
| `1` | Failure, or `cua do` reported an error. |
| `2` | Invalid argument, or an ambiguous sandbox name (qualify it: `local:NAME`). |
| `3` | Not found: sandbox, window, skill or image (or an image not published yet). |
| `4` | Not supported, or not configured (for example no provider credentials). |
| `5` | No cua-spacesd answered, or a transport failure. |
| `6` | Unauthenticated or permission denied (by Cua or your cloud account). |
| `7` | Not enough free disk space (see `cua cache`). |
| `130` | Cancelled (Ctrl-C during a create): what it made was removed. |
