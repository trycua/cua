### `cua auth login`

Log in (browser sign-in; `--remote` for a device code), then offer to set up your AI coding agents.

```text output
cua auth login [OPTIONS]
```

| Flag | Short | Type | Default | Description |
| --- | --- | --- | --- | --- |
| <span id="cua-auth-login--agents"></span>`--agents` |  | string |  | Agents: `all` (installed), `none`, or ids such as `claude,codex,hermes` (`cua agents detect` lists every supported agent). |
| <span id="cua-auth-login--mcp-command"></span>`--mcp-command` |  | string |  | Command agents launch for the MCP server (default: the `cua` on PATH, else this binary). |
| <span id="cua-auth-login--no-browser"></span>`--no-browser` |  | boolean | `false` | Do not open a browser; print the URL. |
| <span id="cua-auth-login--remote"></span>`--remote` |  | boolean | `false` | Sign in from another device with a code (for SSH sessions and computers without a browser). |
| <span id="cua-auth-login--no-onboarding"></span>`--no-onboarding` |  | boolean | `false` | Skip the agent onboarding prompt. |
| <span id="cua-auth-login--skills-only"></span>`--skills-only` |  | boolean | `false` | Only install skills. Alias: `--no-mcp`. |
| <span id="cua-auth-login--mcp-only"></span>`--mcp-only` |  | boolean | `false` | Only configure the MCP server. Alias: `--no-skills`. |
| <span id="cua-auth-login--yes"></span>`--yes` | `-y` | boolean | `false` | Answer yes to every prompt. |
| <span id="cua-auth-login--force"></span>`--force` |  | boolean | `false` | Replace skill folders cua did not write (the old one is backed up). |

**Examples**

```bash test="cli-shape" id="ref-cua-auth-login"
# Sign in with the browser
cua auth login

# Sign in over SSH with a device code
cua auth login --remote

# Sign in and set up Claude Code without prompts
cua auth login --agents claude -y
```

```text output

```

| Argument | Type | Default | Description |
| --- | --- | --- | --- |
| `<TARGET>` | string | optional | Sandbox to check: `local:<name>`, `direct:<host:port>`, a bare name, or a spacesd URL. Omit for the host checks only. |

| Flag | Type | Default | Env var | Description |
| --- | --- | --- | --- | --- |
| <span id="cua-doctor--image"></span>`--image` | string |  |  | Image to resolve for the image checks (default: the sandbox's). |
| <span id="cua-doctor--arch"></span>`--arch` | string |  |  | Architecture to resolve the image for (default: the sandbox's, else this host's). |
| <span id="cua-doctor--format"></span>`--format` | `human` \| `json` \| `junit` | `human` |  | Output format (`--json` selects json). |
| <span id="cua-doctor--effects"></span>`--effects` | `none` \| `virtual` | `none` |  | Which guest checks may act on the guest. |
| <span id="cua-doctor--only"></span>`--only` | string |  |  | Guest check ids or groups to run (comma separated). Repeatable. |
| <span id="cua-doctor--skip"></span>`--skip` | string |  |  | Guest check ids or groups to skip. Repeatable. |
| <span id="cua-doctor--timeout"></span>`--timeout` | integer | `240` |  | Guest budget in seconds. |
| <span id="cua-doctor--token"></span>`--token` | string |  | `CUA_ENV_TOKEN` | spacesd token for a URL target (default: CUA_ENV_TOKEN). |
| <span id="cua-doctor--shim"></span>`--shim` | string |  |  | Check an image without cua-spacesd through its own API instead: `computer-server=<url>`, `osworld=<url>` or `mcp=<url>`. |

| <span id="cua-doctor--machine"></span>`--machine` | string |  |  | Check a machine's health instead, as its own cua daemon sees it (the checks the Machines page shows): another of your machines by name or id, over the relay, the mesh or its direct address, or `this`. |
| <span id="cua-doctor--expect"></span>`--expect` | string |  |  | Fail unless the build running in the guest is the expected one: COMPONENT=WANT with WANT `sha256:<hex>` (the executable), `git:<sha>` or a version (repeatable). Components: cua-spacesd, cua-driver, or an overlay name. `cua sb create --overlay` prints the sha256 to pass. |
| <span id="cua-doctor--strict"></span>`--strict` | boolean | `false` |  | Fail on warnings and on required checks that were skipped. |

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Success. |
| `1` | Failure, or `cua do` reported an error. |
| `2` | Invalid argument, or an ambiguous sandbox name (qualify it: `local:NAME`). |
| `3` | Not found: sandbox, window, skill or image (or an image not published yet). |
| `4` | Not supported, or not configured (for example no provider credentials). |
| `5` | No cua-spacesd answered, or a transport failure. |
| `6` | Unauthenticated or permission denied (by Cua or your cloud account). |
| `7` | Not enough free disk space (see `cua cache`). |
| `130` | Cancelled (Ctrl-C during a create): what it made was removed. |
