### `cua host setup`

Set this computer up for unattended access: install cua-spacesd as a service that joins the cua.ai relay as your account (default) or serves on a direct ip:port. By default it shares this computer's desktop and, on a computer set up for the first time through the relay, provides Spaces to your devices (a host in your pool: `cua run` jobs and `--on auto` Spaces can run here, within its limits). `--share` picks what it shares: `desktop`, `spaces` (its own desktop stays private), `both` or `none`; `cua host config` changes it later. A computer set up before keeps what it provides. Running it again with the same options changes nothing (a stopped service starts again).

```text output
cua host setup [OPTIONS]
```

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| <span id="cua-host-setup--pair"></span>`--pair` | string |  | Join with a one-time pairing code (or add-machine link) made in the Cua Spaces app or with `cua host pair`, instead of signing in here. The computer joins the account (or team) that made it. |
| <span id="cua-host-setup--name"></span>`--name` | string |  | Display name (default: the host name). |
| <span id="cua-host-setup--allow"></span>`--allow` | string |  | Also allow this account (id or email). Repeatable. |
| <span id="cua-host-setup--driver-bin"></span>`--driver-bin` | path |  | cua-spacesd binary (default $CUA_SPACESD_BIN, a bundled one, or the release download). |
| <span id="cua-host-setup--runner"></span>`--runner` | string | `auto` | auto \| systemd \| launchd \| app-helper \| windows-task \| process. On a Mac with the Cua Spaces app, auto is app-helper: the service runs as the app's own login item ("Cua Spaces"). |
| <span id="cua-host-setup--share"></span>`--share` | `desktop` \| `spaces` \| `both` \| `none` |  | What this computer shares: its own desktop (screen, input, shell, files), the Spaces it creates for your enrolled devices (Lume macOS VMs, Docker Linux containers), both, or neither (refused). Default: the desktop, plus Spaces on a new relay setup; a computer set up before keeps what it provides. |
| <span id="cua-host-setup--max-spaces"></span>`--max-spaces` | integer |  | Provided Spaces at once (default 4; 0: no limit). |
| <span id="cua-host-setup--remote"></span>`--remote` | boolean | `false` | When sign-in is needed, use a device code to approve it in a browser on another computer. The account session is not saved. |
| <span id="cua-host-setup--dedicated"></span>`--dedicated` | boolean | `false` | This computer exists only for Cua work (a cloud instance made for it; `cua cloud add aws` sets its hosts up this way): jobs may run in its own Space (`kind = "machine"`), with its GPU and drivers as they are. Never on a computer you also use: there jobs run in macOS VMs or containers. |

**Examples**

```bash test="cli-shape" id="ref-cua-host-setup"
# Join the cua.ai relay as your account (shares this desktop and provides Spaces to your devices)
cua host setup

# Share this desktop only
cua host setup --share desktop

# A spare computer: do not share its desktop, run Spaces for your devices
cua host setup --share spaces --name "Mac mini (spare)"

# Add this computer with a one-time code from the Cua Spaces app (Add a computer) or `cua host pair`: no sign-in needed here
cua host setup --pair K7QM-4XPB-2RHD
```

### `cua host pair`


| <span id="cua-host-pair--name"></span>`--name` | string |  | Name the computer gets (default: its own host name). |
| <span id="cua-host-pair--expires"></span>`--expires` | integer | `30` | Minutes until the code expires (1 to 1440). |
| <span id="cua-host-pair--revoke"></span>`--revoke` | string |  | Revoke an unused code by id (`pc_…`). |
| <span id="cua-host-pair--no-wait"></span>`--no-wait` | boolean | `false` | With --team: print the code and exit instead of waiting; add the computer later with `cua team add-machine <team> relay:<id>`. |

**Examples**

### `cua host config`

Show or change what this computer shares: its own desktop, and whether it creates Spaces for your other devices.


| Flag | Type | Default | Description |

| <span id="cua-host-config--provide-spaces"></span>`--provide-spaces` | `on` \| `off` |  | Create Spaces for your enrolled devices: on \| off. |
| <span id="cua-host-config--max-spaces"></span>`--max-spaces` | integer |  | Provided Spaces at once (0: no limit). |

| <span id="cua-host-config--max-memory"></span>`--max-memory` | integer |  | Memory in GB the Spaces other machines create here may use in total (0: no limit). |
| <span id="cua-host-config--max-disk"></span>`--max-disk` | integer |  | Disk in GB the Spaces other machines create here may use in total (0: no limit). |
| <span id="cua-host-config--max-run-time"></span>`--max-run-time` | integer |  | Minutes a Space created here by another machine may run before it is stopped (0: no limit). |
| <span id="cua-host-config--repo-cache"></span>`--repo-cache` | `on` \| `off` |  | The repo cache: on \| off. It keeps verified copies of public git repositories on this machine so a repeat `git clone` in a Space starts from one (never private repositories, never anything off this machine's disk). |
| <span id="cua-host-config--repo-cache-size"></span>`--repo-cache-size` | string |  | The most disk the repo cache may use, in GB (`auto`: the smaller of 5 GB and a tenth of the free disk). The least recently used repositories go first. |

**Examples**

```bash test="cli-shape" id="ref-cua-host-config"
cua host config

# Stop sharing this desktop; keep providing Spaces
cua host config --desktop off --provide-spaces on
cua host config --max-spaces 6

# Give the Spaces other machines create here at most 32 GB of memory and 200 GB of disk in total, and stop each after 8 hours (0: no limit)
cua host config --max-memory 32 --max-disk 200 --max-run-time 480

# Keep no copies of public git repositories on this machine, or at most 2 GB
cua host config --repo-cache off
cua host config --repo-cache on --repo-cache-size 2
```

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Success. |
| `1` | Failure, or `cua do` reported an error. |
| `2` | Invalid argument, or an ambiguous sandbox name (qualify it: `local:NAME`). |
| `3` | Not found: sandbox, window, skill or image (or an image not published yet). |
| `4` | Not supported, or not configured (for example no provider credentials). |
| `5` | No cua-spacesd answered, or a transport failure. |
| `6` | Unauthenticated or permission denied (by Cua or your cloud account). |
| `7` | Not enough free disk space (see `cua cache`). |
| `8` | No room on the machine: its VMs are at their memory or CPU limit, or it is low on memory. |
| `130` | Cancelled (Ctrl-C during a create): what it made was removed. |
