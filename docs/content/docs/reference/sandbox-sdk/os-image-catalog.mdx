## VM images

VM images boot a guest operating system. A containerDisk is an OCI image that
packages a VM disk; it is not a desktop container that can be started with
`docker run`.

Hyprland and cwm are intentionally excluded because their Docker runtime checks
did not pass. The 24 previously blocked catalog definitions are also excluded.
Docker and VM qualification are independent: a working VM image does not imply
a qualified Docker variant, or vice versa.

These are **systemd-based containers requiring rootful Docker, `--privileged`
and a private cgroup namespace on an isolated, disposable Linux host**. They are
not a tenant isolation boundary or a drop-in replacement for an unprivileged
container. Rootless Docker, gVisor and Modal compatibility is not established.
Never expose the Docker socket or bind host PID/network/cgroup namespaces.

For example, run the pinned XFCE image on the isolated Linux Docker host:

```bash
docker run --rm --name nixos-xfce --privileged --cgroupns=private \
```
