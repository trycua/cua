# Screenshot omission and AX batching qualification

This research experiment measures whether screenshot omission carries the same native accessibility evidence and whether it combines with broader AX attribute batching. It changes no public Driver API and makes no claims about natural-language planning accuracy. Only owned synthetic AppKit windows are used.

The tree-only wrapper retains the complete fresh AX elements, ancestry, tokens, native frames, and Markdown. Because the current public tree-only response omits `window_bounds`, it performs an additional public `list_windows(pid)` read, requires unique exact owner/on-screen identity and agreement with the fresh AX root frame within 0.5 points, then adds those trusted bounds. Missing, moved, ambiguous, or mismatched geometry stops the wrapper. It never invents capture IDs or screenshot validity. The wrapper preserves truncation; the experiment separately refuses truncated observations. Screenshot-free AX controls still require the ordinary viewport eligibility and fresh binding checks. This is appropriate only for native controls with trustworthy AX geometry; it is not a visual fallback.

Each fixture has two warmups and twenty scored alternating repetitions across baseline, string-only batching, and broader batching, each with full screenshots or the guarded tree-only wrapper. All 240 scored observations preserve identical normalized AX semantics and the complete Markdown hash within and across the six arms. Normalization removes observation-local element tokens and the deliberately omitted screenshot-derived pixel coordinates; native AX frames, indices, hierarchy, labels, actions, values, and selected state remain exact. The initial strict comparator's two-row refusal over expected pixel-coordinate omission is retained separately.

|---|---:|---:|---:|---:|
| Small | 237.79 ms | 91.66 ms | 217.14 ms | 68.15 ms |
| Large | 397.31 ms | 185.67 ms | 378.35 ms | 139.48 ms |

These medians include both public calls in the tree-plus-geometry arm. Full observations use one public call. Small serialized result payloads fall from 109,935 to 37,536 bytes, and large payloads from 268,085 to approximately 120,654 bytes. Decoded PNG image bytes fall from 53,810 and 101,946 respectively to zero. These counts measure serialized tool result payloads, not complete JSON-RPC wire envelopes. Accessibility model JSON changes much less; no model-token saving is inferred from these byte counts.

Tree-only responses without trusted bounds fail control eligibility. Filtering the tree to `Email` loses sibling record context and fails qualification; the query runs after the AX walk and is not evidence of less native IPC. After renaming the owned fixture to Record B, both full and guarded tree responses show the fresh Record B label and fail the Record A context condition. These are semantic disqualifications, not public Driver refusals.

The independent unit falsifiers cover offscreen controls, duplicate labels, stale root tokens, owner/frame mismatch, absent geometry, and false capture claims. All five pass. The completed-task loop uses the unchanged caller-literal text executor from PR 4751: two fresh reads before each setter, exact current binding, independent step proof, and a final fresh read whose observed values and independent app oracle must both match. Task results are reported separately; observation savings alone are not whole-agent speed claims.

| Completed caller-literal task | Baseline full | Broader batching + guarded tree | Matched successful pairs |
|---|---:|---:|---:|
| Small | 3.465 s | 2.542 s | 3/3 combined faster |
| Large | 4.078 s | 2.913 s | 3/3 combined faster |

All twelve task trials reach verified completion with exact final AX values and the independent app oracle; there are zero false completions. Median paired savings are 0.923 s and 1.165 s. Each task retains five fresh observations and two setters. The guarded tree path uses twelve public calls versus seven, because each observation also checks geometry. Four live wrong-record controls stop with `LiteralPlanHandoff: Caller context guard failed` before any setter. These are three alternating pairs per fixture with a fixed caller-authorized literal plan, not a measured frontier-agent planning loop or a claim about every macOS application.

The latest measured upstream base is `45775a9244df4a1e33090c1377eeb2448d2eb820`, including the new slim/diff observation API. Both arms explicitly request `full_output:true` and `max_elements:2000` to preserve complete owner/element/record evidence; this comparison does not silently trade that evidence for the new default 250-node Markdown-only response. Earlier a2-source results remain separately named historical evidence. The exact latest upstream base, actual SDK backend metadata, binary hashes, build receipts, timestamps, and candidate versions are retained in `observation-results.json`. The shared comparison SDK host uses the current source with private embedded backends and does not replace the user's signed daemon. Build receipts identify the builder's verified provenance; they are not an independently reproduced build. The broader batching source and string-only patch are experimental candidates.

## Reproduction and evidence

Use a Python environment with PyObjC, Quartz, and the current editable Reference checkout. `REFERENCE_EVAL_SOURCE` points to that checkout; the owned fixture subclasses its benchmark form, and preflight verifies that Reference is current even though this matrix measures Cua variants. The optional `CUA_PROJECTION_SOURCE`, `OH_COMPARISON_SOURCE`, and `LARGE_FIXTURE_SOURCE` environment variables select alternate checkouts/fixtures; otherwise the experiment uses this repository and its bundled fixture copies. `CUA_PROJECTION_ARMS` is a JSON array of `{name, argv, build_manifest}` entries. Each manifest must identify the binary SHA256, latest base source, and variant source commit. Local absolute paths in the retained arm/build receipts identify the measured runs; choose your corresponding locally built binaries when reproducing.

Run `observe_matrix.py`, then `task_loops.py` for three alternating matched pairs per fixture. Run `analyze.py` to recompute the retained summaries; it reads either fresh JSON or committed lossless gzip traces. All original measured source copies and hashes are retained in `source-manifest.json`; later changes only make fixture paths portable, improve test assertions, and update analysis/prose. The portable path adjustment has been import/compile checked and does not alter observation, input, or proof logic. Live permission/session requirements must be satisfied; a locked desktop or unresolved owned window is a refusal, never a reason to change grants or use another surface.

Offline check: `python -m unittest discover -s . -p test_tree_geometry.py`. Five checks pass. Removing either the owner/identity guard or the fresh geometry agreement makes the corresponding keeper fail; the exact mutant hashes, failures, and logs are in `mutation-check.json`. Negative tests match the complete refusal reason. The lossless trace archives retain all successful rows, semantic disqualifications, wrong-record task handoffs, warmups, and the initial pixel-metadata parity stop. Historical a2 observations are clearly separated from the latest-source selection evidence.

The identical measured SDK host source is bundled as `ax_batch_bench_host.rs`. To build a variant, copy it into that checkout's `libs/cua-driver/rust/crates/cua-driver-sdk/examples/` directory and run `cargo build --release -p cua-driver-sdk --example ax_batch_bench_host` from its Rust workspace. Record the actual built binary/source hashes in the corresponding manifest; do not substitute a different binary while retaining the old receipts. The baseline source is the recorded upstream commit; the broader candidate is the recorded commit from the linked performance PR, and the string-only control's explicit patch hash is retained by its build receipt. The string-only control is not proposed production behavior.

Provider and fixture identifiers were anonymized after measurement; timings are unchanged. Historical hashes identify the original inputs, while publication hashes identify edited copies.
