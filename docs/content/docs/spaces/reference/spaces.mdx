### add_space

Add an existing computer as a Space by address and token.

Tries a GetCapabilities handshake with the Space's cua-spacesd first. A local:&lt;name&gt; or cloud:&lt;name&gt; id without one is still a Space, with an empty capability set (its declared services, tunnels and public URLs work); a direct URL without one is added as an MCP Space when it answers MCP initialize (service `mcp`), and refused with spacesd_not_available when it answers neither. The Space is stored in ~/.cua/spaces.json and its token in ~/.cua/spaces-credentials.json (0600). Re-adding the same address updates it.

### create_space

Create a Space: a new sandbox on this computer, on one of your computers, or in the cloud.

Creates a new sandbox where `on` says (local: this computer, free; aws, azure, gcp, hetzner or modal: the user's own cloud account, connected with cloud_connect, billed there; default: the user's default location, else local; with no location and none configured, when a linked cloud has a budget set with cloud_budget, this computer first and the linked clouds when it is full, never past the budget, unless placement.overflow is off; a Space that landed in the user's cloud carries `cloud` and `cloud_place`, the pool host and its price, so say so), waits until it is ready (its spacesd when the image runs one, else its declared services), and registers it as local:&lt;name&gt;. Cua Cloud (on="cloud") has ended and fails with an error that says so. `kind` (auto, container, vm, microvm: the container image with its own kernel, never picked by auto) and `runtime` (auto, or an engine the location offers for the kind) are chosen automatically by default: the canonical Linux image runs as a gVisor container, macOS images as Lume VMs, Windows and disk-only images as VMs (QEMU locally, KubeVirt in the cloud). An impossible combination fails with invalid_placement and lists the valid values. Any image works; without cua-spacesd the capability set is empty. reuse=true returns a reachable registered Space in the same location with the requested services instead of creating one. On the user's own computers: on="auto" creates it on the least-loaded one that can take it (this computer or one signed in to the user's account that provides Spaces; the host refuses when full and the next is asked); on="host:&lt;computer&gt;" creates the Space on a computer set up with `cua host setup --share both` (for example "spin up 2 macOS Spaces on my spare Mac mini" is on="host:spare mac mini", image="macos", count=2). The computer is matched by id, exact name, or the words of its name; when several fit equally the call fails with ambiguous_host listing them (ask the user which, then pass on="host:&lt;id&gt;"). The host runs it with its own runtimes (Lume for macOS VMs on a Mac, Docker for Linux), the Space joins the relay and is returned as relay:&lt;computer&gt; with `host` set. A Mac runs at most two macOS VMs (Apple's macOS license, enforced by Apple Virtualization); a host at a limit fails with limit_exceeded. Only the computer's owner and the accounts it is shared with as editors can create there, from an enrolled device. on="direct:&lt;addr&gt;" is not accepted here: a direct address is one already-running Space, attached with add_space, not a host this call can create on. durable=true (with on="auto") keeps the Space on the user's computers: when its computer goes away it is created again on another one with the same name (its disk starts fresh), list_spaces shows it with `durable`, and delete_space deletes it for good.

### delete_space

Deletes the sandbox of a Space that create_space made (cloud: metering stops; local: the instance is deleted; on one of your computers, on="host:...": that computer deletes it and it leaves the relay) and forgets it. ### stop_space

Turn a Space off: stop it (disk kept, memory freed) or, with suspend, suspend it (memory kept).

Turns a Space off the way its provider can. By default it stops: a local VM (QEMU or Lume) shuts down with its disk kept and gives its memory back to the machine, a local container stops or is suspended as its runtime can, a Space one of your computers provides is stopped by that computer, and a Space in your own cloud (on="aws", "gcp") is stopped there: compute billing stops, its disk stays (storage is still billed); a Hetzner server (on="hetzner") is stopped too, but Hetzner keeps billing a stopped server, so delete it to stop the charge. suspend=true suspends a local container or QEMU VM instead: its memory is kept (so it still uses it) and it resumes where it was. Anything streaming from the Space and any hotspot on it end first. A Modal sandbox, a Space added by address and your own computers on the relay cannot be turned off (wrong_provider); delete_space deletes a Space instead. start_space turns it on again.

### space_job

Run a long command in the Space as a background job: tail its log, cancel it, or get woken when it ends.

Use this instead of space_bash for anything that takes more than a minute (builds, test suites, installs, waiting on CI). `start` returns a job id at once and the command keeps running when you stop, disconnect, or the Space's daemon restarts. Read it with `logs` (pass the returned `next_offset` as `offset` to read on; `follow_ms` waits for output) or `status`; stop it with `cancel`; `list` shows the Space's jobs. Pass `notify: true` to be woken: the Space's thread gets one message `JOB <id> <state> exit=<n> ...` with the end of the log, and as an agent member you receive it as your next turn, so you can end your turn instead of polling. `until` makes a job that waits for a file, a port, a command or a pull request's required checks; its end is the condition. Output is stdout and stderr together. Linux and macOS guests.

| | |
| --- | --- |
| Providers | all (cloud, local, direct, relay) |
| Platforms | all (macos, windows, linux) |
| Metering | free |
| Approval | permission `spaces:space_job`; destructive |
| Swift SDK | `Space.job(_:)` |
| Rust | `Space::job` |

#### Parameters

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `action` | `string` | required | `start` (begin a job), `status` (state and the end of its log), `logs` (read the log from a byte offset), `cancel` (stop it) or `list` (this Space's jobs, newest first). |
| `command` | `string` | none | `start`: the command line, run with `/bin/sh -c` in the background. It keeps running when you or your connection go away. Give this or `until`. |
| `cwd` | `string` | none | `start`: the directory to run in. Default: the Space user's home. |
| `env` | `map of string` | none | `start`: environment variables for the command. |
| `follow_ms` | `integer` | `0` | `logs`: when there is nothing new after `offset` and the job is running, wait up to this many milliseconds (at most 25000) for output or for the job to end. Default 0. At least 0. |
| `job` | `string` | none | `status`, `logs`, `cancel`: the job id `start` returned. |
| `limit` | `integer` | none | `logs`: most bytes to return (default 16000, at most 262144). At least 0. |
| `name` | `string` | none | `start`: a short label for the job ("unit tests"), shown in listings and in the message that wakes you. |
| `notify` | `boolean` | `false` | `start`: wake me when the job ends. The Space's thread gets one message with the job's result and the end of its log, addressed to you when you are an agent member of the Space (so you can finish your turn and sleep), and the person gets a notification. Default false. |
| `offset` | `integer` | none | `logs`: the byte offset to read from (the `next_offset` of the previous call). Without it: the last `limit` bytes. At least 0. |
| `space` | `string` | required | Space id or name. |
| `timeout` | `integer` | none | `start`: seconds before the job is stopped. Default: none. At least 0. |
| `until` | `object` | none | `start`: wait for a condition instead of running `command`. The job ends when the condition holds (exit 0), or after `timeout`. |
| `until.command` | `string` | none | Wait for this shell command to exit 0. |
| `until.file` | `string` | none | Wait for this path to exist in the Space. |
| `until.host` | `string` | `127.0` | With `port`: the host. Default 127.0.0.1. |
| `until.interval` | `integer` | `5` | Seconds between checks (1 to 300). Default 5 (30 for `pr_checks`). At least 0. |
| `until.port` | `integer` | none | Wait for this TCP port to accept connections (on `host`, default 127.0.0.1). 0 to 65535. |
| `until.pr_checks` | `string` | none | Wait for a GitHub pull request's required checks to finish with `gh` (signed in inside the Space): a number, a URL or `owner/repo#123`. The job exits 0 when they pass and 1 when one fails. |
| `wake` | `string` | none | `start` with `notify`: the agent member to wake instead of you. |

#### Result

JSON. `start`: `job`, `state`, `log_command` and a `hint`. `status`, `logs`: `job`, `name`, `state` (`running`, `exited`, `cancelled`, `timed_out` or `lost`), `exit_code`, `signal`, `started_at` and `ended_at` (unix seconds), `elapsed_s`, `size` (log bytes), and for `logs` `offset`, `next_offset`, `text` and `more`. `cancel`: the final status. `list`: `jobs`.

- A job is a command that outlives the call, the connection and a restart of the Space's daemon; its state is files in the Space (`~/.cua/jobs/<id>`). Guests that are not Windows.

### send_file

Send a host file or folder into the Space's Downloads, verified by sha256 on arrival.

The same transfer the Cua Spaces pop-out's Teleport drop zone performs: files land in the Space user's ~/Downloads through the spacesd's TeleportService (chunked, resumable, every file verified by sha256 before it is published). A transfer that does not land, or lands corrupted, is an error and not a reported success.

respect_ignorefiles (default true) applies ONLY when `path` is a folder. It honors `.gitignore` and `.ignore` at the folder root and in every subdirectory (each scoped to its own subtree, so a nested ignore file overrides its parent), plus `.dockerignore` at the root only. All three use gitignore semantics: negation (`!`), directory-only patterns (`foo/`), anchoring, `*`/`?`/`[...]`, `**`, comments, last-matching-rule-wins. As in git, an excluded directory is pruned and `!` cannot re-include anything beneath it. `.git/` is always skipped and symlinks are never followed. For a single named file it has NO effect.

| | |
| --- | --- |
| Providers | all (cloud, local, direct, relay) |
| Platforms | all (macos, windows, linux) |
| Metering | free |
| Approval | permission `spaces:send_file`; destructive |
| Swift SDK | `Space.sendFile(_:into:respectingIgnoreFiles:)` |
| Rust | `Space::send_file` |

#### Parameters

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `path` | `string` | required | Host path (file or folder) to send. |
| `respect_ignorefiles` | `boolean` | `true` | Honor `.gitignore` / `.ignore` (nested) and `.dockerignore` (root only) when sending a folder. Default true. No effect on a single named file. |
| `space` | `string` | required | Space id or name. |
| `target_directory` | `string` | `~/Downloads` | Subdirectory of the Space user's `~/Downloads` to land in. `~/Downloads` and `~/Downloads/<sub>` are accepted too. Default: `~/Downloads` itself. |

#### Result

JSON: `source`, `destination`, `dest`, `kind`, `files` (each `path`, `size`, `sha256`), `bytes`, `respect_ignorefiles`, `skipped_by_ignorefiles`, `skipped_count`, `skipped_by_guest` and `verified`.

#### Errors

[`invalid_argument`](/spaces/reference#invalid_argument), [`not_found`](/spaces/reference#not_found), [`ambiguous_sandbox`](/spaces/reference#ambiguous_sandbox), [`transfer_failed`](/spaces/reference#transfer_failed), [`io`](/spaces/reference#io)

#### Notes

- Unlike `upload`, the copy is verified in the Space by sha256 before the call returns: a transfer that does not land, or lands corrupted, is an error and not a reported success.
- `respect_ignorefiles` applies only when the path is a folder, with gitignore semantics; a file named explicitly is always sent.
- A file of the same name already in the Space is kept: the new copy lands as `name (1).ext` and its path is in `files`.

| `name` | `string` | none | Substring filter; matching tools come back with full input schemas. |
| `service` | `string` | `driver` | Service. A service the Space declares (see `list_spaces`), reached over generic MCP (streamable HTTP), or `driver` (the spacesd's cua-driver registry; `mcp`, `cua-driver` and `computer-server` are aliases unless the Space declares a service by that name). Default: `driver`, or the only declared service of a Space without spacesd. |
| `space` | `string` | required | Space id or name. |

#### Result

JSON: `service`, `count`, `tools` (`name` and `description`; with `name`, also `inputSchema`), `services`, `contract_version`, and a `hint` when no filter was given.

#### Errors

[`invalid_argument`](/spaces/reference#invalid_argument), [`not_found`](/spaces/reference#not_found), [`ambiguous_sandbox`](/spaces/reference#ambiguous_sandbox), [`mcp`](/spaces/reference#mcp)

### call_tool

Call a service tool inside the Space.

Returns the tool's content parts unchanged, images included. A tool-level failure comes back with isError, not as a transport error.

#### Parameters

### space_service

Keep a command running in the Space: restarts, health checks, start on boot, logs.

Keeps a command running in the Space: cua-spacesd starts it at once, starts it again by its `restart` policy when it ends (waiting longer after each quick failure, up to a minute), restarts it when its health check (`http`, `tcp` or `check`, one of them) fails 3 times in a row, starts it when the Space boots unless start_on_boot is false, and keeps its output in a log file in the Space (`logs`). `stop` keeps it stopped, across a reboot too, until `start`. `add` with a name that exists replaces it.

| | |
| --- | --- |
| Providers | all (cloud, local, direct, relay) |
| Platforms | all (macos, windows, linux) |
| Metering | free |
| Approval | permission `spaces:space_service`; destructive |
| Swift SDK | `space.keepRunning.service(_:)` |
| Rust | `Space::keep_service` |

#### Parameters

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `action` | `string` | required | `add` (or replace), `list`, `start`, `stop`, `restart`, `remove` or `logs`. |
| `check` | `string` | none | `add`: health check, a shell command that exits 0 when healthy. |
| `command` | `string` | none | `add`: the shell command line to keep running. |
| `http` | `string` | none | `add`: health check, a URL that answers 2xx or 3xx. |
| `name` | `string` | none | Service name (every action but `list`): lowercase letters, digits, `-`, `_` and `.`. |
| `restart` | `string` | none | `add`: when to start it again: `always` (default), `on-failure` or `never`. |
| `space` | `string` | required | Space id or name. |
| `start_on_boot` | `boolean` | none | `add`: start it when the Space boots (default true). |
| `tail_bytes` | `integer` | none | `logs`: bytes from the end (default 64 KiB). At least 0. |
| `tcp` | `string` | none | `add`: health check, `host:port` that accepts a connection. |

#### Result

JSON: `add`, `start`, `stop` and `restart` give the service (`name`, `command`, `state`, `pid`, `restarts`, `last_end`, `probe_error`, `restart`, `start_on_boot`, `log_path`); `list` gives `services`; `logs` gives `logs` (text); `remove` gives `removed`.

#### Errors

[`invalid_argument`](/spaces/reference#invalid_argument), [`not_found`](/spaces/reference#not_found), [`ambiguous_sandbox`](/spaces/reference#ambiguous_sandbox), [`capability_missing`](/spaces/reference#capability_missing)
