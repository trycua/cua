`fork_many` and `fork_groups` start many sandboxes from checkpoints at once and return a `ForkBatch` whose events arrive as they happen: where each group went, the copy of a checkpoint to a machine that lacked it, each fork ready (or failed, alone), and last the summary. With `on = "auto"` a group's forks go to one of your machines, so they share the checkpoint's memory there; groups of different checkpoints spread over the least-loaded machines; a checkpoint is copied (and its files verified by SHA-256) to a machine that lacks it, straight from the machine that holds it, else from the fallback that `publish_checkpoint` fills; forks of a machine that fails are placed again. The CLI is `cua sb fork-many` and `cua sb publish`.

## Batch methods

Methods of [`Sandboxes`](/cua-sdk/reference/sandbox#sandboxes).

### `Sandboxes.fork_many`

Forks checkpoint `source` `count` times at once and returns the
running batch: each fork is reported as soon as it is ready (or
failed: one failure does not stop the others). `source` may also be
a local sandbox, running or stopped: it is checkpointed once (memory
saved once, shared copy-on-write by the forks on QEMU) and that
checkpoint is deleted with the last of its forks. With `on = "auto"`
the forks go to your machines that provide Spaces: each group
(`group_size` forks) to one machine, groups spread over the least
loaded ones, the checkpoint copied (and verified) to a machine that
lacks it first; a machine that fails has its forks placed again on
another.

### `Sandboxes.publish_checkpoint`

Uploads checkpoint `name` to `fallback` (S3, or a folder every
machine mounts), so batches on your other machines copy it from
there when this machine cannot be reached. Files already there are
not uploaded again. Returns the bytes uploaded.

## `ForkBatch`

A running batch of forks. Its events as they happen
(`ForkBatch.next`), or all of it (`ForkBatch.collect`).

Returned by [`Sandboxes.fork_groups`](#sandboxesfork_groups), [`Sandboxes.fork_many`](#sandboxesfork_many).

| Method | Description |
| --- | --- |
| [`collect`](#forkbatchcollect) | Waits for the whole batch: every fork (ready or failed), by index, and the summary. |
| [`next`](#forkbatchnext) | The next event: a placement, a copy's progress, a fork that is ready (or failed), and last the summary. |

### `ForkBatch.collect`

Waits for the whole batch: every fork (ready or failed), by index,
and the summary. After some or all of the events were read with
`ForkBatch.next`, it still returns the whole batch: the forks
already read plus the rest, with the summary.

## `ForkManyOptions` record

Batched fork options. For `Sandboxes.fork_many` and
`Sandboxes.fork_groups`.

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `on` | `Option<String>` | `None` | Where: `local` (this machine, the default), `auto` (your machines that provide Spaces, this one included, least loaded first) or `host:<machine>`. |
| `group_size` / `groupSize` | `u32` | `0` | Forks per group for `Sandboxes.fork_many` (0: all in one group). A group's forks go to one machine, so they share the checkpoint's memory there. |
| `max_parallel_per_host` / `maxParallelPerHost` | `u32` | `0` | Forks started at once on one machine (0: 4). |
| `name_prefix` / `namePrefix` | `String` | `""` | Names are `<prefix>-<n>` (empty: `<checkpoint>-<random>`). |
| `cpus` | `u32` | `0` | vCPUs each fork is counted as when placing (0: 1, as forks of one world are mostly idle). |
| `memory_mb` / `memoryMb` | `u64` | `0` | Memory (MiB) each fork is counted as when placing (0: the checkpoint's). |
| `retries` | `u32` | `0` | Times forks of a machine that failed (or was full) are placed again on another (0: once). |
| `no_retry` / `noRetry` | `bool` | `false` | Never place failed forks again: report them. |
| `fallback` | [`Option<SnapshotFallbackOptions>`](#snapshotfallbackoptions-record) | `None` | Where machines fetch a checkpoint they lack when the one that holds it cannot be reached. |

## `SnapshotFallbackOptions` record

A fallback copy of checkpoints. Your machines fetch a checkpoint there
when the machine that holds it cannot be reached
(`Sandboxes.publish_checkpoint` puts it there). Set `s3_bucket` (S3,
with each machine's AWS credentials) or `dir` (a folder every machine
mounts, such as your Cua Volume).

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `s3_bucket` / `s3Bucket` | `String` | `""` | S3 bucket. |
| `s3_prefix` / `s3Prefix` | `String` | `""` | Key prefix in the bucket (`cua-snapshots/`). |
| `s3_region` / `s3Region` | `String` | `""` | Region (empty: each machine's AWS default). |
| `s3_endpoint` / `s3Endpoint` | `String` | `""` | An S3-compatible endpoint (empty: AWS). |
| `dir` | `String` | `""` | A folder every machine mounts (`~` is each machine's home), for example `~/Cua Volume/snapshots`. |
