### `cua spaces egress`

Choose which destinations a Space may reach: block some, or block everything except a few. The machine the Space runs on enforces it, outside the guest (nothing in the guest, root included, can change it). Replaces the whole policy at once; `--clear` removes it. By IP address or CIDR (`all` is every address), not by hostname. DNS works only while the resolver the guest uses is not blocked.

.

Everything is allowed unless a rule says otherwise: every --deny entry blocks that destination, and every --allow entry is an exception that wins over a --deny. --allow alone blocks nothing. Loopback, replies to connections made to the Space and IPv6 neighbor discovery are never filtered. Containers (runc, gVisor), and QEMU and Firecracker VMs on Linux take a policy; macOS VMs, Apple Containerization, Cua Cloud and your own cloud accounts refuse one and say why.

```text output
cua spaces egress [OPTIONS] <SPACE>
```

| Argument | Type | Default | Description |
| --- | --- | --- | --- |
| `<SPACE>` | string | required | Space id or name. |

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| <span id="cua-spaces-egress--deny"></span>`--deny` | string |  | A destination to block (IPv4/IPv6 address, CIDR or `all`; repeat for more). Repeatable. |
| <span id="cua-spaces-egress--allow"></span>`--allow` | string |  | A destination that stays reachable where --deny blocks it (repeat for more). Repeatable. |
| <span id="cua-spaces-egress--clear"></span>`--clear` | boolean | `false` | Remove the policy. |

**Examples**

```bash test="cli-shape" id="ref-cua-spaces-egress"
# Block one network
cua spaces egress studio --deny 10.0.0.0/8

# Only 1.1.1.1 and one network stay reachable
cua spaces egress studio --deny all --allow 1.1.1.1 --allow 203.0.113.0/24

# Back to unrestricted
cua spaces egress studio --clear
```

### `cua host setup`

Set this computer up for unattended access: install cua-spacesd as a service that joins the cua.ai relay as your account (default) or serves on a direct ip:port. By default (the `desktop` profile) it shares this computer's desktop, also with `--provide-spaces`; `--profile spare` or `--no-desktop --provide-spaces` provides Spaces only, so it is a host in your pool (`cua run` jobs run in Spaces there) whose own desktop stays private. Running it again with the same options changes nothing (a stopped service starts again).

```text output
cua host setup [OPTIONS]
```

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| <span id="cua-host-setup--pair"></span>`--pair` | string |  | Join with a one-time pairing code (or add-machine link) made in the Cua Spaces app or with `cua host pair`, instead of signing in here. The computer joins the account (or team) that made it. |
| <span id="cua-host-setup--name"></span>`--name` | string |  | Display name (default: the host name). |
| <span id="cua-host-setup--allow"></span>`--allow` | string |  | Also allow this account (id or email). Repeatable. |
| <span id="cua-host-setup--driver-bin"></span>`--driver-bin` | path |  | cua-spacesd binary (default $CUA_SPACESD_BIN, a bundled one, or the release download). |
| <span id="cua-host-setup--runner"></span>`--runner` | string | `auto` | auto \| systemd \| launchd \| app-helper \| windows-task \| process. On a Mac with the Cua Spaces app, auto is app-helper: the service runs as the app's own login item ("Cua Spaces"). |
| <span id="cua-host-setup--profile"></span>`--profile` | `desktop` \| `spare` |  | What this computer is for: `desktop` (share this desktop; the default, also with `--provide-spaces`) or `spare` (do not share the desktop; provide Spaces). |
| <span id="cua-host-setup--max-spaces"></span>`--max-spaces` | integer |  | Provided Spaces at once (default 4; 0: no limit). |
| <span id="cua-host-setup--remote"></span>`--remote` | boolean | `false` | When sign-in is needed, use a device code to approve it in a browser on another computer. The account session is not saved. |
| <span id="cua-host-setup--desktop"></span>`--desktop` | boolean | `false` | Share this computer's own desktop as a Space. |
| <span id="cua-host-setup--no-desktop"></span>`--no-desktop` | boolean | `false` | Do not share this computer's own desktop (screen, input, shell, files): relayed callers reach only the Spaces it provides. |
| <span id="cua-host-setup--provide-spaces"></span>`--provide-spaces` | boolean | `false` | Create Spaces for your enrolled devices on this computer's runtimes (Lume macOS VMs, Docker Linux containers). On its own it keeps the default `desktop` profile, so this computer's desktop is shared too; add `--no-desktop` (or use `--profile spare`) to provide Spaces only. |
| <span id="cua-host-setup--no-provide-spaces"></span>`--no-provide-spaces` | boolean | `false` | Do not create Spaces for other devices. |
| <span id="cua-host-setup--dedicated"></span>`--dedicated` | boolean | `false` | This computer exists only for Cua work (a cloud instance made for it; `cua cloud add aws` sets its hosts up this way): jobs may run in its own Space (`kind = "machine"`), with its GPU and drivers as they are. Never on a computer you also use: there jobs run in macOS VMs or containers. |

**Examples**

```bash test="cli-shape" id="ref-cua-host-setup"
# Join the cua.ai relay as your account (shares this desktop)
cua host setup

# A spare computer: do not share its desktop, run Spaces for your devices
cua host setup --profile spare --name "Mac mini (spare)"
cua host setup --no-desktop --provide-spaces

# Add this computer with a one-time code from the Cua Spaces app (Add a computer) or `cua host pair`: no sign-in needed here
cua host setup --pair K7QM-4XPB-2RHD
```

## `cua share`

Share a link to a port, a file or a folder that opens on your other signed-in devices (never localhost): `cua share 3000`, `cua share ./report.html`, `cua share ls`, `cua share stop ID`.

```text output
cua share [OPTIONS] <TARGET>
       cua share <COMMAND>
```

| Argument | Type | Default | Description |
| --- | --- | --- | --- |
| `<TARGET>` | string | required | What to share: a port (`3000`), a port in a Space (`space:NAME:3000`), or a file or folder (`./report.html`, `./build/`). Paths are read-only; use `./ls` for a file called `ls`. |

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| <span id="cua-share--ttl"></span>`--ttl` | string |  | How long the share lasts (`10m`, `1h`, 60s to 24h). Public shares default to 1h; the others have no end unless you set one. |
| <span id="cua-share--name"></span>`--name` | string |  | A name for `cua share ls` (and `cua share stop NAME`). |
| <span id="cua-share--team"></span>`--team` | boolean | `false` | Share with the members of your team. |
| <span id="cua-share--public"></span>`--public` | boolean | `false` | Anyone with the link can open it. Expires (default 1h, 60s to 24h). |

**Examples**

```bash test="cli-shape" id="ref-cua-share"
# A dev server on this machine, for your own devices (phone included)
cua share 3000

# A port inside a Space
cua share space:dev:3000

# A report or a folder, read-only
cua share ./report.html
cua share ./build/

# Members of your team
cua share 3000 --team

# Anyone with the link, for an hour
cua share ./report.html --public --ttl 1h

# What is shared, and stop it
cua share ls
cua share stop share-1a2b3c4d5e6f
cua share stop all
```

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Success. |
| `1` | Failure, or `cua do` reported an error. |
| `2` | Invalid argument, or an ambiguous sandbox name (qualify it: `local:NAME`). |
| `3` | Not found: sandbox, window, skill or image (or an image not published yet). |
| `4` | Not supported, or not configured (for example no provider credentials). |
| `5` | No cua-spacesd answered, or a transport failure. |
| `6` | Unauthenticated or permission denied (by Cua or your cloud account). |
| `7` | Not enough free disk space (see `cua cache`). |
| `8` | No room on the machine: its VMs are at their memory or CPU limit, or it is low on memory. |
| `130` | Cancelled (Ctrl-C during a create): what it made was removed. |
