### `cua auth login`

Log in (browser sign-in; `--remote` for a device code), then offer to set up your AI coding agents.

```text output
cua auth login [OPTIONS]
```

| Flag | Short | Type | Default | Description |
| --- | --- | --- | --- | --- |
| <span id="cua-auth-login--agents"></span>`--agents` |  | string |  | Agents: `all` (installed), `none`, or ids such as `claude,codex,hermes` (`cua agents detect` lists every supported agent). |
| <span id="cua-auth-login--mcp-command"></span>`--mcp-command` |  | string |  | Command agents launch for the MCP server (default: the `cua` on PATH, else this binary). |
| <span id="cua-auth-login--no-browser"></span>`--no-browser` |  | boolean | `false` | Do not open a browser; print the URL. |
| <span id="cua-auth-login--remote"></span>`--remote` |  | boolean | `false` | Sign in from another device with a code (for SSH sessions and machines without a browser). |
| <span id="cua-auth-login--no-onboarding"></span>`--no-onboarding` |  | boolean | `false` | Skip the agent onboarding prompt. |
| <span id="cua-auth-login--skills-only"></span>`--skills-only` |  | boolean | `false` | Only install skills. Alias: `--no-mcp`. |
| <span id="cua-auth-login--mcp-only"></span>`--mcp-only` |  | boolean | `false` | Only configure the MCP server. Alias: `--no-skills`. |
| <span id="cua-auth-login--yes"></span>`--yes` | `-y` | boolean | `false` | Answer yes to every prompt. |
| <span id="cua-auth-login--force"></span>`--force` |  | boolean | `false` | Replace skill folders cua did not write (the old one is backed up). |

**Examples**

```bash test="cli-shape" id="ref-cua-auth-login"
# Sign in with the browser
cua auth login

# Sign in over SSH with a device code
cua auth login --remote

# Sign in and set up Claude Code without prompts
cua auth login --agents claude -y
```

#### `cua auth provider set`

Store a provider key, read from stdin (no echo on a terminal). An environment variable of the same name wins over the stored key.

```text output
cua auth provider set [OPTIONS] <NAME>
```

| Argument | Type | Default | Description |
| --- | --- | --- | --- |
| `<NAME>` | string | required | Provider (`e2b`, `daytona`, `modal`). |

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| <span id="cua-auth-provider-set--var"></span>`--var` | string |  | Only this variable (for example MODAL_TOKEN_SECRET). |

**Examples**

```bash test="cli-shape" id="ref-cua-auth-provider-set"
# Prompt for E2B_API_KEY (no echo)
cua auth provider set e2b

# One variable only
cua auth provider set daytona --var DAYTONA_API_KEY
```

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Success. |
| `1` | Failure, or `cua do` reported an error. |
| `2` | Invalid argument, or an ambiguous sandbox name (qualify it: `local:NAME`, `cloud:NAME`). |
| `3` | Not found: sandbox, window, skill or image (or an image not published yet). |
| `4` | Not supported, or not configured (for example no Fleet credentials). |
| `5` | No cua-spacesd answered, or a transport failure. |
| `6` | Unauthenticated or permission denied (by Cua, Fleet or your cloud account). |
| `7` | Not enough free disk space (see `cua cache`). |
| `130` | Cancelled (Ctrl-C during a create): what it made was removed. |
