Start a sandbox on your own machine, run a command in it, take a screenshot and
drive its desktop. A Linux sandbox works on macOS, Linux and Windows. A macOS
sandbox needs an Apple silicon Mac.

## Before you start

- For a Linux sandbox: macOS, Linux or Windows with Docker, or another local
  runtime (`cua runtime doctor` lists them).
- For a macOS sandbox: an Apple silicon Mac on macOS 14 or later, with about
  40 GB of free disk and 8 GB of free memory.

## Install

```bash skip="host-install"
curl -fsSL https://cua.ai/install.sh | sh -s -- --cli-only   # or: pip install cua, npm i -g @trycua/cua
```

## Linux sandbox

Create it, run a command in it and take a screenshot:

```bash test="cli-shape" id="cua-quickstart-local"
cua sb create linux --name dev
cua sb exec dev "uname -a"
cua sb screenshot dev -o dev.png
```

![cua sb create, ls, exec and view for a local Linux sandbox](/img/cua-cli/cua-sb-create.png)

`exec` prints the guest's kernel line and exits with the command's status.
`dev.png` is the sandbox desktop. With `--json` the result is structured:

```bash test="cli-shape" id="cua-quickstart-json"
cua --json sb exec dev pwd   # {"stdout": ..., "stderr": ..., "returncode": 0}
```

### Drive the desktop

`--wait desktop` returns once the desktop accepts input (display, window
manager and Cua Driver). `cua do` input waits for it too, and fails when the
input reaches no window.

```bash test="cli-shape" id="cua-quickstart-do"
cua sb create linux --name desk --wait desktop
cua do switch desk
cua do launch xfce4-terminal   # waits for the new window and focuses it
cua do type "echo hello"
cua do key enter
```

### Remove the Linux sandboxes

```bash test="cli-shape" id="cua-quickstart-rm"
cua sb rm dev
cua sb rm desk
```

## macOS sandbox

### Set up the runtime

```bash test="cli-shape" id="macos-runtime-setup"
cua runtime doctor
cua runtime setup lume   # installs Lume if it is missing
```

### Create it

```bash test="cli-shape" id="macos-sb-create"
cua sb create macos --name mac
```

```text output
ID         STATUS  LOCATION  KIND  RUNTIME  EXPIRES
local:mac  ready   local     vm    lume     -
```

`macos` is `ghcr.io/trycua/macos:26` (Tahoe). `macos:sequoia` is `:15`. The first
create pulls the image (23 GB, about 8 minutes). Later creates clone it and are
ready in about 25 seconds. The Tahoe image starts cua-spacesd at login, with its
screen and accessibility permissions already granted.

### Run a command

```bash test="cli-shape" id="macos-sb-exec"
cua sb exec mac -- sw_vers
```

```text output
ProductName:		macOS
ProductVersion:		26.5.2
BuildVersion:		25F84
```

`exec` runs through cua-spacesd and keeps stdout, stderr and the exit code
apart. The Sequoia image has no cua-spacesd, so there `exec` runs over SSH
(`lume ssh`).

### Take a screenshot and open the desktop

```bash test="cli-shape" id="macos-sb-screenshot"
cua sb screenshot mac -o desktop.png
```

```text output
wrote desktop.png (1024x768)
```

![The desktop of a local macOS Tahoe sandbox](/img/cua-cli/macos-sandbox-desktop.png)

```bash test="cli-shape" id="macos-sb-view"
cua sb view mac
```

```text output
Viewer for mac: http://192.168.64.63:3211/viewer/#ticket=****&files=%2FUsers%2Flume
```

`view` opens cua-spacesd's HTML5 viewer in your browser with a short-lived
ticket (`--no-open` prints the URL instead). On Sequoia, screenshots come over
the VM's VNC endpoint and `view` opens the display with `lume attach`.

### Remove it

```bash test="cli-shape" id="macos-sb-rm"
cua sb rm mac
```

The pulled image stays as a stopped base VM for the next create. `cua cache ls`
lists it.

### Use the SDK instead

```python skip="macos-vm"
from cua_sandbox import Image, Sandbox

async with Sandbox.ephemeral(Image.macos()) as sb:
    print((await sb.shell.run("sw_vers")).stdout)
    png = await sb.screen.screenshot()
```

`sb.shell` and `sb.screen` go through cua-spacesd, the same path as the CLI.
