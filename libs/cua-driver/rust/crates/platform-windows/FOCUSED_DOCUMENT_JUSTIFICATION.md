# Focused Document production-size justification

The supplied previous-head gate report records production **+466/-16, net +450**, against limits of **add ≤200 and net ≤100**. Tests and documentation are separately **+133/-1**; generated files are **+1/-1**, excluded from the budget. These are the supplied figures, not a recount of this revision.

## Required chunks

- `src/uia/focused_document.rs` (**+337/-0**): isolates the Windows COM operation and apartment lifetime; checks exact foreground window, process, focused Document identity, writable empty value, and TextPattern support; rechecks focus and value immediately before replacing the value; verifies text, end caret, and target identity afterward. Cancellation and the write-start marker distinguish safe fallback from an uncertain write that must never be replayed. Stage-specific failures retain diagnostics without treating partial writes as success. The pre-write rereads are necessary because provider calls can yield while focus or content changes: initial eligibility alone cannot justify a later replacement.
- `src/tools/impl_.rs` (**+112/-14**): admits the route only for implicit non-Chromium targets, connects desktop and foreground delivery to the same asynchronous attempt, and translates outcomes into existing action evidence. Not-applicable probes retain the existing input route; confirmed writes carry verification evidence; uncertain writes stop with non-retryable results. Removing the result mapping would lose truthful effect reporting or risk duplicate input.
- `src/uia/windows_enum.rs` (**+16/-2**): exposes the existing bounded, cancellation-aware, single-flight worker through a focused-document entry point with a 200 ms deadline. Reusing this worker prevents a wedged COM provider from accumulating threads and carries cancellation into the write boundary. A separate worker implementation would duplicate that machinery; an unbounded direct call would lose latency and resource protection.
- `src/uia/mod.rs` (**+1/-0**): registers the module so the shared route can call it.

## Shrinking performed and alternatives considered

The current implementation consolidates the empty/writable/selection decision into one tested eligibility gate, eliminating the duplicate empty-document and eligibility returns. DocumentRange availability remains a separately named stage rather than a duplicate eligibility decision. The desktop and foreground branches now share one asynchronous attempt helper instead of duplicating dispatch and outcome handling. Both consolidations are retained unchanged.

Further shrinking by dropping the second focus/value read was considered and rejected: SetValue replaces the whole value, so intervening user input must prevent the write. Collapsing all staged probe failures into a generic failure would remove actionable failure-stage diagnostics without eliminating the underlying COM calls or safety checks. Removing post-write selection/value/identity verification would weaken the meaning of confirmed success. Reimplementing the deadline path locally would increase duplication rather than shrink it. This revision therefore documents the remaining budget exception rather than removing behavior or compressing code solely to reduce line counts.
