You need a Mac with macOS 14 or later, and Claude Code, Codex or Cursor. On
Windows or Linux, see [Windows](#windows) or [Linux](#linux).

## 1. Install

Paste this line into Terminal:

```bash skip="host-install"
/bin/bash -c "$(curl -fsSL https://cua.ai/driver/install.sh)"
```

The installer connects Claude Code, Codex and Cursor if they are on your Mac,
then opens a guide window for the next step.

## 2. Turn on two switches

The guide asks for two permissions, one at a time:

1. **Step 1 of 2: Let Cua Driver use your mouse and keyboard.** Switch on
   CuaDriver under **Accessibility**.
2. **Step 2 of 2: Let Cua Driver see your screen.** Switch on CuaDriver under
   **Screen & System Audio Recording**.

The guide moves on by itself when each switch is on. The installer then checks
that everything works and prints **Cua Driver works**.

## 3. Ask your agent

Start a new Claude Code, Codex or Cursor session and send:

```text output
Use Cua Driver to open TextEdit in the background, type "Hello from Cua Driver"
into a new document, and read the text back from the window.
```

The line appears in TextEdit while the window you are working in stays in
front. The cursor you see moving is Cua Driver's, not yours.

If something's off, run:

```bash skip="host-macos-permissions"
cua-driver test
```

It checks both switches, reads the screen, moves Cua Driver's cursor and types
a line into TextEdit in the background. It ends with **Cua Driver works**, or
with what to fix. See [Troubleshoot](/cua-driver/guides/troubleshoot) for more.

## Connect another agent

The installer connects the agents it finds. If you install Claude Code, Codex
or Cursor later, run:

```bash skip="host-install"
cua-driver connect
```

It adds the Cua Driver tools (an MCP server named `cua-driver`) and the Cua
Driver skill to each of them. Start a new session afterwards. For Hermes,
OpenClaw, Prime Agent, Gemini, local models and others, see
[Connect your agent](/cua-driver/guides/connect-your-agent).

## Turn on the switches by hand

If the guide window didn't open, for example because you installed over SSH,
open **System Settings > Privacy & Security** and switch on CuaDriver under
both **Accessibility** and **Screen & System Audio Recording**.

![CuaDriver listed under Accessibility in System Settings with its toggle switched off](https://github.com/user-attachments/assets/d149fe5a-28cb-460c-8868-4eda80d540a4)

![CuaDriver listed under Screen & System Audio Recording in System Settings with its toggle switched off](https://github.com/user-attachments/assets/469308b5-84d7-4fd6-a580-e62925120337)

If CuaDriver is not in a list, click **+** under it, open **Applications**,
choose **CuaDriver**, then click **Open** and **Allow**.

<Callout type="warn">
  macOS may offer to quit and reopen CuaDriver when you switch it on. Accept: Cua Driver only
  picks up a new permission after it restarts. Then run `cua-driver test` to check. If macOS
  reports a permission as on but `cua-driver test` says it is off, see [Reset stale macOS
  permissions](/cua-driver/guides/troubleshoot#reset-stale-macos-permissions).
</Callout>

## Windows

In PowerShell, in the desktop session you want the agent to use:

```powershell test="cli-shape" id="cua-driver-autostart-kick"
irm https://cua.ai/driver/install.ps1 | iex
cua-driver autostart kick
```

The installer tries to register Cua Driver to start at sign-in, and `kick`
starts it now. If registration was skipped or failed, run `cua-driver serve`
in a terminal in your desktop session and leave it open. Over SSH, see
[Windows over SSH](/cua-driver/guides/vms-and-remote#windows-over-ssh).

Then run `cua-driver connect` in a second terminal, and send the prompt from
[step 3](#3-ask-your-agent) with Notepad in place of TextEdit.

## Linux

Cua Driver needs an x86_64 desktop with X11 or XWayland and AT-SPI 2. In a
terminal inside the desktop session:

```bash test="cli-shape" id="cua-driver-serve"
/bin/bash -c "$(curl -fsSL https://cua.ai/driver/install.sh)"
~/.local/bin/cua-driver serve
```

Leave it open, so the driver can reach the display and accessibility bus. On
a minimal Debian or Ubuntu image, first run
`sudo apt install libxi6 at-spi2-core`.

On GNOME, also install the bundled WinRects helper (no `sudo` needed), then
log out and back in once so Shell loads it:

```bash skip="host-install"
~/.cua-driver/packages/current/wayland-helper/install.sh
gnome-extensions info winrects@cua   # State: ACTIVE
```

Then run `cua-driver connect` in a second terminal, and send the prompt from
[step 3](#3-ask-your-agent) with your desktop's text editor in place of
TextEdit.

## Approve macOS permissions on managed Macs, CI hosts and VMs

Without someone at the Mac to switch on the two permissions, use the first
option that fits:

1. **Managed Macs:** push an MDM profile with a Privacy Preferences Policy
   Control (PPPC) payload for `com.trycua.driver`. It pre-approves
   Accessibility. macOS does not let MDM grant Screen Recording silently, so
   set `ScreenCapture` to `AllowStandardUserToSetSystemService`: a standard user
   can then switch CuaDriver on without an administrator password.
2. **Hosts you operate (dev boxes, CI hosts, VMs):** when you tell your agent in
   the task that it may approve Cua Driver's prompts on this host, it runs
   `cua-driver permissions grant` and clicks **Allow** through the host's own
   VNC or Screen Sharing server. It clicks only prompts that name CuaDriver,
   and it logs each approval.
3. **Everyone else:** switch them on yourself, as in [step 2](#2-turn-on-two-switches).

Your agent never approves a prompt for another app, never does this without your
explicit authorization in the task, and never does it on a machine you do not
own or run. Approvals survive signed updates, so you approve once per Mac. The Cua
Driver skill has the example profile, the VNC helper and the exact steps: see
[Install and approve permissions](https://github.com/trycua/cua/blob/main/libs/cua-driver/rust/Skills/cua-driver/MACOS.md#install-and-approve-permissions).
