## Act on a window without focusing it, raising it or moving the pointer
What changes what the user sees: activating an app (NSRunningApplication activateWithOptions_, SetFrontProcess), AXRaise, writing AXFrontmost, AXMain, AXFocused or AXFocusedWindow on the user's app, events posted at the HID or session tap (CGEventPost) and cursor warps (CGWarpMouseCursorPosition), and opening any menu (AXShowMenu, AXPress on an AXPopUpButton, AXMenuButton or AXMenuBarItem, a right-click). What does not: AXUIElementCopyAttributeValue reads, AXUIElementPerformAction(el, "AXPress") on buttons, checkboxes, radio buttons, rows and menu items, AXUIElementSetAttributeValue of AXValue or AXSelected, and events posted to one process (CGEventPostToPid, SLEventPostToPid). Writing AXFocused on an element of a background app moves focus inside that app only; read the user's frontmost app and its AXFocusedWindow before and after to confirm. Window ids: CGWindowListCopyWindowInfo(kCGWindowListOptionOnScreenOnly, 0) lists windows front to back (kCGWindowNumber, kCGWindowOwnerPID, kCGWindowBounds, kCGWindowLayer); the private _AXUIElementGetWindow(AXUIElementRef, uint32_t *wid) -> AXError in ApplicationServices maps an AX window to its id.

## Type text or keys into an app that is not frontmost
Make sure the receiving element has keyboard focus inside its app first: read the app's AXFocusedUIElement, and write AXFocused = True on the field if it is not (background app only). Then post key events to the app's pid: CGEventCreateKeyboardEvent(None, 0, down), CGEventKeyboardSetUnicodeString(ev, len(ch), ch) for text, or a virtual key code (Return 36, Tab 48, Delete 51, Forward Delete 117, Escape 53, arrows 123-126) with CGEventSetFlags for modifiers, then CGEventPostToPid(pid, ev). Read the field's AXValue back afterwards. Some apps ignore posted keys unless one of their windows is the app's key window, even while they stay in the background. For those, make the window key without activating the app with SkyLight event records, then post through SLEventPostToPid (see "Make a background window key without activating its app").

## Make a background window key without activating its app
Private SkyLight calls, loaded with ctypes.CDLL("/System/Library/PrivateFrameworks/SkyLight.framework/SkyLight"): uint32_t CGSMainConnectionID(void); CGError SLSGetWindowOwner(uint32_t cid, uint32_t wid, uint32_t *owner_cid); CGError SLSGetConnectionPSN(uint32_t cid, ProcessSerialNumber *psn /* 8 bytes */); CGError SLPSPostEventRecordTo(ProcessSerialNumber *psn, uint8_t *record); void SLEventPostToPid(pid_t pid, CGEventRef ev) (pass the pyobjc event's pointer, ev.__c_void_p__()). A record is 248 zeroed bytes with byte 0x04 = 0xF8, byte 0x08 = kind and the window id little-endian at 0x3C..0x3F. Focus: kind 0x0D with byte 0x8A = 1 for the window that should become key (2 defocuses the app's current key window). Make-key: kinds 0x01 then 0x02, each with byte 0x3A = 0x10 and bytes 0x20..0x2F = 0xFF. Send a defocus for the app's current key window if there is one, wait about 0.12 s, the focus record, wait again, then the make-key pair, all to the owner's PSN. Confirm with the app's AXFocusedWindow (it should be that window) and AXFocusedUIElement (it should not be empty); repeat once if not. A dialog of the app that holds key focus wins: close or answer it first. Then post keys with SLEventPostToPid. The user's frontmost app and key window are not touched.

## Choose an option in a pop-up button or a list without opening a menu in front of the user
Combo boxes take an AXValue write. A web <select> takes typed characters while closed: write AXFocused on it (inside its own background app), post the option's label as Unicode key events to the pid, wait about 1 s before typing into another select of the same app (type-ahead buffers merge), and read its AXValue back. Never post Space, Up or Down to a focused pop-up: that opens its menu. A native pop-up button lists its items only while its menu is open, and opening it takes key focus from the user's app (AppKit calls SLPSStealKeyFocusReturningID) and lifts the target window. To hand key focus back while the menu is open: install a per-process listen tap on the user's frontmost app, CGEventTapCreateForPid(front_pid, kCGHeadInsertEventTap, kCGEventTapOptionDefault, 1 << 21, callback, None), on a run loop thread; when an event of type 21 arrives with integer field 64 == 0x4000 and field 73 == the target pid, return None (the user's app never sees the loss) and release the theft with int32 SLPSReleaseKeyFocusWithID(int32 id), which returns 0 for a live theft id (ids come from one session-wide counter, so scan upward from a recent value). Open the menu with AXPress on the pop-up from a separate thread (the call blocks while the menu tracks), find the item among the pop-up's AXMenu children by AXTitle and AXPress it. If the target window rose above the user's window, AXRaise the user's own focused window again. Read the pop-up's AXValue back.

## Run a menu command without opening the menu
Menu items exist in the app's accessibility tree while closed: AXMenuBar of AXUIElementCreateApplication(pid) -> AXMenuBarItem children (AXTitle) -> one AXMenu -> AXMenuItem children. AXPress the AXMenuItem itself, not the menu-bar title (pressing the title opens the menu). A disabled item has AXEnabled False. AXMenuItemCmdChar and AXMenuItemCmdModifiers give its shortcut.

## Click in a background window
Prefer the element's AX action (AXPress, AXConfirm, AXPick) or an AXValue / AXSelected write. When only a pixel click works, post mouse events to the pid: CGEventCreateMouseEvent(None, kCGEventLeftMouseDown / Up, (x, y) screen point with top-left origin, kCGMouseButtonLeft); set integer fields kCGMouseEventClickState (1) = 1, kCGEventTargetUnixProcessID (40) = pid, and the window id in fields 51, kCGMouseEventWindowUnderMousePointer (91) and kCGMouseEventWindowUnderMousePointerThatCanHandleThisEvent (92); stamp the point with the private CGEventSetWindowLocation(CGEventRef, CGPoint) (exported by CoreGraphics); post a kCGEventMouseMoved to the same point first, then down and up, through SLEventPostToPid or CGEventPostToPid. Apps that render web content may also need an off-screen primer click at (-1, -1) before the real one, and the window made key as in "Make a background window key without activating its app".

## Drag in a background window
Same event recipe as a background click, stretched over a gesture, all to the pid and never to the HID tap: mouse-moved at the start point; mouse-down; a 30 ms hold; 10 to 20 kCGEventLeftMouseDragged events interpolated along the path about 15 to 25 ms apart; the last drag at the drop point; a 50 ms pause; mouse-up at the drop point. Every event carries the target pid (field 40), the window id (fields 51, 91, 92), one gesture id in field 58 (any nonzero integer, the same on every event of the gesture), click state 1 on down, drags and up, and CGEventSetWindowLocation with its own point. Make the window key first. A drag that starts a system drag-and-drop session follows the real pointer instead, so check the result (the list order, the moved item's AXPosition) and use an accessibility alternative when the list offers one: AXSelected rows with AXIncrement / AXDecrement, move-up or move-down buttons, or menu commands.

## Save an image to disk
Capture a CGImage (CGWindowListCreateImage(CGRectNull, kCGWindowListOptionIncludingWindow, window_id, kCGWindowImageBoundsIgnoreFraming) for one window, even behind others; CGRectInfinite with kCGWindowListOptionOnScreenOnly for the screen; or ScreenCaptureKit's SCScreenshotManager). Write it with ImageIO, with no NSData or NSBitmapImageRep step: dest = CGImageDestinationCreateWithURL(NSURL.fileURLWithPath_(path), "public.png", 1, None); CGImageDestinationAddImage(dest, image, None); CGImageDestinationFinalize(dest) returns True when the file is written. Use "public.jpeg" for JPEG. Crop first with CGImageCreateWithImageInRect.

## Open a file in an app without bringing it to the front
NSWorkspace.sharedWorkspace().openURLs_withApplicationAtURL_configuration_completionHandler_([NSURL.fileURLWithPath_(path)], app_url, config, handler) with config = NSWorkspaceOpenConfiguration.configuration() and config.setActivates_(False). Find app_url with URLForApplicationWithBundleIdentifier_ or a running app's bundleURL(). The handler is called on a run loop: spin NSRunLoop.currentRunLoop().runUntilDate_ until it has been called (it receives the NSRunningApplication and an NSError or None). Then find the new window with CGWindowListCopyWindowInfo and check the user's frontmost app did not change. In a browser window that is already open, the address field takes a file:// URL as an AXValue write followed by a Return key posted to the browser's pid.

## Apps whose accessibility tree is empty or shallow
Apps that render web content build their web accessibility tree only when an assistive client asks: write AXManualAccessibility = True on the application element (AXEnhancedUserInterface if that is unsupported), wait up to 2 s, then read the window again; an AXWebArea with children appears. AXUIElementSetMessagingTimeout(el, seconds) bounds a slow app. AXUIElementCopyElementAtPosition(system_wide, x, y) finds the element at a screen point.

## Check that an action worked
A zero AXError means the app accepted the request, not that anything changed. Read the element back (AXValue, AXSelected, the window's AXTitle, the static texts under it) or capture the window, and compare with what you expected before reporting success.
