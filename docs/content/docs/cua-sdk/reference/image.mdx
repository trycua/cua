Images are references: the functions here resolve and normalise them without pulling anything. `ImageBuild` layers and a `RegistrySecret` go into `SandboxCreateOptions`.

Python programs usually use the high-level API instead: [`cua_sandbox.Image`](/cua-sdk/reference/python/sandbox#image).

`canonical_image` names one public repository per OS; `CUA_IMAGE_LINUX`, `CUA_IMAGE_WINDOWS` and `CUA_IMAGE_MACOS` override it. The [image catalog details](/cua-sdk/reference/os-image-catalog) lists each image's variants, and [runtime support](/cua-sdk/reference/runtime-support) where each one runs.

## `resolve_image`

Resolves `reference` for `backend` (`auto`, `local`, `provider`,
`container`/`docker`/`gvisor`, `vm`/`qemu`/`kubevirt`, `lume`)
on `arch` (`amd64`/`arm64`; `None` = this host).
`reference` is literal (`ubuntu:24.04` is Docker Hub's image): no
alias applies here; use `image_alias` or `canonical_image` first.
Raises `NotFound` (no such image: e.g. a tag only the local engine has),
`Unauthenticated` (the registry refused the credentials), `Unsupported`
(no variant the backend runs, e.g. a macOS image on a cloud provider).
Blocks while the registry is read (cached for five minutes).

## `canonical_image_tier`

The canonical image for `os`, `version` and `tier`: `slim` (the minimum
that passes `cua-spacesd doctor --strict`; CI and benchmarks use it),
`full` or `None` (the default, with dev tooling), on macOS `xcode`
/ `xcode-<X.Y>` (full plus one pinned Xcode) or, on Linux, `docker`
(slim plus the Docker engine, a VM: `-docker-disk`). The tag is
`<os-version>[-<tier>]` (`ghcr.io/trycua/linux:24.04-slim`); the
resolver finds its `-disk` sibling. `CUA_IMAGE_<OS>` overrides only the
default full image. Raises `ImageNotPublished` for a tier CI has not
published yet, `InvalidArgument` for an unknown tier, `xcode` outside
macOS or `docker` outside Linux.

## Pools

A pool is sandboxes of one shape the cua daemon keeps ready on its machine: `min` at all times (one starts again as soon as one is taken), up to `max` while creates come faster than sandboxes start, and none after `idle_ms` without a create. A create with `pool` set to its name gets the pool's image and size and takes a ready sandbox. Without pools, the daemon keeps sandboxes ready only where repeated creates of a shape pay for it (`cua daemon status` says why). Pools need a daemon (`Cua.connect`) and run on this machine only (`on = "local"`); the CLI is `cua sb pool`.

Python programs usually use the high-level API instead: [`create_pool`](/cua-sdk/reference/python/sandbox#pools-on-this-machine).

## Pool methods

Methods of [`Sandboxes`](/cua-sdk/reference/sandbox#sandboxes).

### `Sandboxes.create_pool`

Creates a pool: sandboxes of `image` (and `options`' shape) kept
ready on this machine by `cua daemon`, so that a create from the
pool (`SandboxCreateOptions.pool`) takes one in about 0.1 s.

- `min`: kept ready at all times; one starts again as soon as one is
created from the pool.
- `max`: the most kept ready (not counting those created from the
pool); above `min` only while creates come faster than sandboxes
start. Default: `min`.
- `idle_ms`: after this long without a create from the pool it keeps
none ready, until the next create (which starts on the default tier
and refills it). Default: never.

Pools run on this machine (`on = "local"`, the default). Without a
pool, the daemon keeps sandboxes ready only where repeated creates of
a shape pay for it; a pool asks for them explicitly. Creating a pool
with the name of an existing one updates it.

## Create options

`Sandboxes.create` takes one `SandboxCreateOptions`. Every field means the same thing locally and in the cloud; `on` picks where the sandbox runs, `kind` and `runtime` what runs it.

Python programs usually use the high-level API instead: [`Sandbox.create` parameters](/cua-sdk/reference/python/sandbox#sandboxcreate).

## `SandboxCreateOptions` record

Options for `Sandboxes.create`.

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `on` | `Option<String>` | `None` | Where it runs: `local`, `direct:<addr>` (an existing machine running cua-spacesd) or a registered provider. `None` (the default): the user default (`default.on` in `~/.cua/config.toml`, `CUA_DEFAULT_ON`, else `local`). `cloud` fails with the "Cua Cloud has ended" error. |
| `kind` | `Option<String>` | `None` | What kind of machine: `auto`, `container` or `vm`. `None`: the user default (`default.kind`, else `auto`: macOS and Windows images are VMs, an image with a container rootfs is a container, a disk-only image is a VM). |
| `runtime` | `Option<String>` | `None` | Which engine: `auto` or one the location offers for the kind (local `gvisor`, `runc`, `qemu`, `lume`). `None`: the user default (`default.runtime`, else `auto`, the safest available). A local sandbox with sidecars needs `runc` where gVisor would run. A combination that does not exist is `InvalidPlacement`, listing the valid values. |
| `image` | `String` | `""` | Image reference. A `pool:<name>` image fails with the "Cua Cloud has ended" error. |
| `name` | `Option<String>` | `None` | Name. `None`: ephemeral (no state file; deleted with the sandbox). |
| `token` | `Option<String>` | `None` | spacesd token. |
| `pool` | `Option<String>` | `None` | Create from this pool: locally, a pool made with `Sandboxes.create_pool` (the sandbox gets the pool's image and shape and takes one of its ready sandboxes in about 0.1 s; `image` may be left empty). |
| `os` | `Option<String>` | `None` | Guest OS (`linux`, `macos`, `windows`). |
| `cpus` | `Option<u32>` | `None` | vCPUs. |
| `memory_mb` / `memoryMb` | `Option<u64>` | `None` | Memory (MiB). |
| `ports` | `Vec<u16>` | `[]` | Extra guest ports (local: published). |
| `services` | `HashMap<String, u16>` | `[:]` | Named services (name → guest port). `env` defaults to 3211. |
| `wait_for` / `waitFor` | [`Vec<ReadinessProbe>`](#readinessprobe-record) | `[]` | Readiness probes. |
| `ready_timeout_ms` / `readyTimeoutMs` | `Option<u32>` | `None` | Readiness budget (default 10 min). |
| `env` | `HashMap<String, String>` | `[:]` | Guest environment (local: container environment or cloud-init; values are not secrets). |
| `ttl_seconds` / `ttlSeconds` | `Option<u32>` | `None` | Lifetime backstop in seconds: the platform deletes the sandbox this long after it stops being kept alive (a provider sandbox such as `on = "e2b"`: its lifetime). `None`: the platform's default. |
| `command` | `Option<Vec<String>>` | `None` | The sandbox's command (argv), replacing the image's entrypoint. Same meaning local (container ENTRYPOINT, or run by cloud-init in a Linux VM) and in the cloud (the template command with `processMode: Run`, on gVisor and KubeVirt). |
| `sidecars` | [`Vec<Container>`](#container-record) | `[]` | Sidecar containers, addressed by name (see `Container`). |
| `registry_secret` / `registrySecret` | [`Option<RegistrySecret>`](#registrysecret-enum) | `None` | Credentials for a private `image` (and sidecar images on its registry). |
| `build` | [`Option<ImageBuild>`](#imagebuild-record) | `None` | Image layers built on top of `image` (a build into the local container engine, cached by content). |
| `network` | `Option<String>` | `None` | Guest network: `"default"` (unset) gives outbound network, like a Docker container; `"none"` cuts it while published ports still work. Only local QEMU VMs honour `"none"`; containers and Lume reject it. |
| `overlays` | [`Vec<Overlay>`](/cua-sdk/reference/sandbox#overlay-record) | `[]` | Binaries to inject once the sandbox is up, so tests run the build under test and not the copy the image bundles (see `Overlay`; the same as calling `Sandbox.overlay` after create). Needs cua-spacesd in the image, or a local container. |
| `keep_on_failure` / `keepOnFailure` | `bool` | `false` | Keep a named sandbox whose readiness check fails (its VM or container, and its record) to debug it. `false` (the default): a failed create deletes what it made. Ephemeral sandboxes are always deleted. |
| `gpu` | `Option<String>` | `None` | A GPU option of the runtime it runs on (`Spaces.gpu_support` lists them): `paravirtual` (a macOS VM on Lume: GPU acceleration, experimental), `virgl` (QEMU on Linux), `nvidia` (a runc container on Linux), a contrib provider's GPU type; `auto` picks the runtime's own. `None` (the default): no GPU. |
| `headless` | `bool` | `false` | A Space without a desktop: only cua-spacesd runs (exec, files, processes, MCP), with no display, window manager or audio. For shell and RL workloads it starts several times faster and fits many more per machine. Images without cua-spacesd are unaffected; a `command` of your own is kept. |
| `spacesd` | `Option<bool>` | `None` | Whether an image without cua-spacesd gets a static one injected, so any OCI image is a full Space (local containers and microVMs: exec, files, ports). `None` (the default): yes. `Some(false)` runs the image as it is. |
| `profile` | `Option<String>` | `None` | A size profile: defaults for what is left unset. `"rollout"`: 1 vCPU, 1024 MiB and `headless` (a local VM gets no display hardware, so many more fit on one machine), for RL rollouts and agent episodes that mostly wait. `None` or `"default"`: 2 vCPUs, 4096 MiB. |
| `forkable` | `Option<bool>` | `None` | A fork source (a "bake" sandbox): a local QEMU VM's guest RAM is a shared file, so its checkpoints take milliseconds and forks of them share its pages (`Sandboxes.checkpoint`, `Sandboxes.fork`). Other kinds ignore it. `None` (the default): not one. |

## `ReadinessProbe` record

A user-declared readiness probe. With no probes a sandbox is ready as
soon as its provider reports it running; nothing assumes a guest daemon.

Name a declared service (`service = "mcp"`) or a guest port.

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `port` | `u16` | `0` | Guest port (0 with `service`). |
| `http_path` / `httpPath` | `Option<String>` | `None` | HTTP path; `None` is a TCP connect probe. |
| `http_status` / `httpStatus` | `Option<u16>` | `None` | Exact HTTP status to wait for; `None` accepts any 2xx. |
| `service` | `Option<String>` | `None` | A declared service whose guest port to probe (instead of `port`). |

## `Container` record

An extra container next to a sandbox (a compose-style sidecar),
addressed by name on every runtime: the sandbox reaches it at its
`name` (on its `ports`), it reaches the sandbox at `main`, and
`services` may name its ports (`{"db": 5432}`). Local containers run it
in the sandbox's network namespace (`localhost` works too; needs
`runtime="runc"`). Local VM sandboxes refuse sidecars. With sidecars the
service names `main`, `sidecars` and `sc` are reserved.

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `image` | `String` |  | Image reference. |
| `command` | `Option<Vec<String>>` | `None` | argv replacing the image's entrypoint. |
| `env` | `HashMap<String, String>` | `[:]` | Environment (plain values, not secrets). |
| `ports` | `Vec<u16>` | `[]` | Ports it listens on. |
| `name` | `Option<String>` | `None` | Name, unique within the sandbox, and its hostname (not `main`). Unset: from the image (`redis`). |
