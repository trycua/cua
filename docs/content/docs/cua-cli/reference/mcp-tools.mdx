## Spaces tools

The Spaces contract: register, claim and release Spaces, run commands, move files, stream, run agents and teleport.

These tools are the [Spaces contract](/spaces/reference), with the same names and schemas on every surface. Each links to its entry there (parameters, result, errors, providers, metering); `cua mcp` gates each one behind the permission `spaces:<tool>`.

## Sandbox tools

### `sandbox_list`

List sandboxes: local and direct ones by default, each row with location (local or direct). Pass location to list only one kind. When the user is signed in and has other machines, a note after the rows names them and the route to use: a machine's own desktop is the Space relay:&lt;id&gt; (computer tools and space_bash take it as `space`), and new Spaces go to one with create_space on="host:&lt;name&gt;".

Permission: `sandbox:list`.

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| <span id="sandbox_list--location"></span>`location` | `"local" \| "direct"` |  | Only sandboxes in this location: local or direct (default: all). |

### `sandbox_create`

Create a sandbox from any image. `on` says where (local, the default unless the user configured another with `cua config set default.on`), `kind` what (auto, container, vm, microvm) and `runtime` which engine (auto, or gvisor, runc, qemu, lume, firecracker, vz, containerization); an impossible combination fails and lists the valid values. To browse the web, pass browser=true (and optionally url): it starts the canonical Linux image, registers it as a Space, launches Chromium with a throwaway profile inside it and returns the space, session, target_id and tab_id to pass to call_tool with the in-sandbox browser tools (browser_navigate, get_browser_state, browser_click, browser_type). Pass command, env and services to run a server in it, for example an MCP server: services &#123;"mcp": 8765&#125;. Without browser=true it does not register a Space: to reach its MCP server with list_tools/call_tool (service="mcp"), use create_space instead (same arguments), or add this one with add_space (address local:&lt;name&gt;).

Permission: `sandbox:create`.

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| <span id="sandbox_create--browser"></span>`browser` | `boolean` |  | Start a browser in it, ready for the cua-driver browser tools (default image: the canonical Linux image). |
| <span id="sandbox_create--command"></span>`command` | `string[]` |  | Entrypoint override (argv), for example ["python", "-m", "my_mcp"]. |
| <span id="sandbox_create--env"></span>`env` | `object` |  | Environment variables (string values). |

| <span id="sandbox_create--name"></span>`name` | `string` |  | Sandbox name. |

### `sandbox_pool_list`

List the pools: sandboxes of one image kept ready on this machine (min always, up to max while creates come fast), each with how many are ready and why.

Permission: `sandbox:list`.

No parameters.

### `sandbox_pool_create`

Create a pool (or update the pool of that name): sandboxes of one image kept ready on this machine, min at all times (refilled right after each create from it) and up to max while creates come faster than sandboxes start. sandbox_create with pool=&lt;name&gt; then takes one in about 0.1 s. Use it before creating many sandboxes of one kind (an agent loop, a batch); without pools, ready sandboxes are kept only where repeated creates pay for it.

Permission: `sandbox:pools`.

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| <span id="sandbox_pool_create--cpus"></span>`cpus` | `integer` |  | vCPUs of each sandbox. |
| <span id="sandbox_pool_create--env"></span>`env` | `object` |  | Environment variables (string values). |
| <span id="sandbox_pool_create--idle_seconds"></span>`idle_seconds` | `integer` |  | After this long without a create from the pool it keeps none ready until the next one (default: never). |
| <span id="sandbox_pool_create--image"></span>`image` | `string` | required | Image its sandboxes run (for example linux). |
| <span id="sandbox_pool_create--kind"></span>`kind` | `string` |  | auto (default), container, vm or microvm. |
| <span id="sandbox_pool_create--max"></span>`max` | `integer` |  | Most kept ready, not counting those created from the pool (default: min). |
| <span id="sandbox_pool_create--memory_mb"></span>`memory_mb` | `integer` |  | Memory (MiB) of each sandbox. |
| <span id="sandbox_pool_create--min"></span>`min` | `integer` |  | Sandboxes kept ready at all times (default 1). |
| <span id="sandbox_pool_create--name"></span>`name` | `string` |  | Pool name (lower-case letters, digits, '-'; default: a new one). |

## Teleport tools

### `teleport_browser_session`

Teleport the user's signed-in session for specific sites (for example github.com) from their Firefox or Chrome into a sandbox, through the Cua Keyvault. Name each site: nothing is selected by default and there is no all-sessions option. The first call moves nothing: it files a Keyvault request and returns consent_required, a summary and a request_id. Show the summary to the user; they approve it in Cua (Touch ID or password). Then call again with the request_id to move exactly those sites. Use it only when the user asks to browse as themselves.

Permission: `teleport:browser`.

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| <span id="teleport_browser_session--browser"></span>`browser` | `"firefox" \| "chrome"` | required | firefox or chrome (chromium, brave and edge profiles use chrome). |
| <span id="teleport_browser_session--duration_minutes"></span>`duration_minutes` | `integer` |  | How long the sandbox may keep them (default 15, at most 1440). |
| <span id="teleport_browser_session--name"></span>`name` | `string` | required | Sandbox ref (local:&lt;name&gt;, direct:&lt;host:port&gt;) or a name unique across locations. |
| <span id="teleport_browser_session--reason"></span>`reason` | `string` |  | Why, in a few words; shown to the user as unverified. |
| <span id="teleport_browser_session--request_id"></span>`request_id` | `string` |  | The request_id from the first call, after the user approved it in Cua. |
| <span id="teleport_browser_session--sites"></span>`sites` | `string[]` | required | The exact sites to teleport, for example ["github.com"]. |

**Example arguments**

```json
{"name":"<name>","browser":"firefox","sites":["<site>"]}
```

## Share tools

Share tools are `cua share` for agents: use them for any link to something you ran, never localhost. `share` opens the link once to check it loads. See [Share a link to anything you run](/cua-cli/guides/share-a-link).

### `share`

Get a link to something you ran, that opens on the user's other signed-in devices (phone included): a dev server or dashboard on a port, a port in a Space, or a file or folder (read-only). ANY link to something you ran (a preview, a dashboard, a report, a file) must come from this tool: never hand the user localhost, 127.0.0.1 or a Space-internal address, which they cannot open. It creates a persistent share (it keeps working after this session, until `ttl`, share_stop, or the Space is deleted), then opens the link once itself and returns `check`. Only send the link when `check.ok` is true; if it is false, say so, fix what is wrong (start the server, fix the path) and check again with a new share. Default access is private (only the user's cua.ai account); team shares it with the user's team; public makes a link anyone can open (expires, default 1h) and needs the user's say-so.

Permission: `share:create`.

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| <span id="share--access"></span>`access` | `string` |  | private (default: the user's own devices), team, or public (anyone with the link; expires). |
| <span id="share--name"></span>`name` | `string` |  | A name for share_list. |
| <span id="share--target"></span>`target` | `string` | required | What to share: a port on this machine ("3000"), a port in a Space ("space:NAME:3000"), or a file or folder path (absolute, or relative to the server's directory). |
| <span id="share--ttl"></span>`ttl` | `string` |  | How long it lasts: 10m, 1h, 24h (60s to 24h). Public shares default to 1h; others have no end. |

**Example arguments**

```json
{"target":"<target>"}
```

### `share_list`

The active shares: id, link, access, what each serves and when it ends.

Permission: `share:read`.

No parameters.

### `share_stop`

Stop a share so its link stops working at once. Pass its id or name from share_list, or "all".

Permission: `share:stop`.

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| <span id="share_stop--id"></span>`id` | `string` | required | A share's id or name, or "all". |

**Example arguments**

```json
{"id":"<id>"}
```

## Run tools

Run tools are `cua sb run` and `cua sb runs` for agents: on this machine by default, or with `on="auto"` on the least-loaded of the machines signed in to your account that provide Spaces ([Use all your machines](/spaces/guides/add-a-computer#use-all-your-computers)). They need the cua daemon of Cua Spaces.

### `space_run`

Run a command in new Spaces, `count` times (each in its own Space, deleted afterwards): on this machine by default, or with on="auto" on the least-loaded of the user's machines that provide Spaces (signed in to their account, or added by address), or on one machine by name. Returns the run id at once; read progress and results with space_runs. A run on the user's machines keeps going when this machine sleeps. Each job's result is recorded once, but a job may run more than once when a machine is lost, so make it safe to repeat. For batch work (many browser sessions, tests, renders); for one interactive Space use create_space.

Permission: `runs:run`.

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| <span id="space_run--command"></span>`command` | `string[]` | required | The command and its arguments (run without a shell; use ["sh", "-c", "..."] for one). |
| <span id="space_run--concurrency"></span>`concurrency` | `integer` |  | Most at once (default: as many as the machines take). |
| <span id="space_run--count"></span>`count` | `integer` |  | How many times to run it (default 1, at most 10000). |
| <span id="space_run--cpus"></span>`cpus` | `number` |  | CPUs reserved for each (default 1). |
| <span id="space_run--env"></span>`env` | `object` |  | Environment variables for the command. |
| <span id="space_run--image"></span>`image` | `string` |  | Image of each Space (default: the canonical Linux image). |
| <span id="space_run--kind"></span>`kind` | `string` |  | container, vm or microvm (default: what the image is). |
| <span id="space_run--memory_mb"></span>`memory_mb` | `integer` |  | Memory reserved for each, in MiB (default 1024). |
| <span id="space_run--on"></span>`on` | `string` |  | local (default: this machine), auto (the least-loaded of your machines), or a machine's name. |
| <span id="space_run--runtime"></span>`runtime` | `string` |  | A runtime: gvisor, runc, firecracker, ... (default: auto). |
| <span id="space_run--timeout_secs"></span>`timeout_secs` | `integer` |  | How long each may run (default 600). |

**Example arguments**

```json
{"command":["<command>"]}
```

### `space_runs`

A run's progress and results (pass `run`: its summary, counts by state, done, and its jobs with machine, attempt, exit code, stdout, stderr), one job with its output (`run` and `job`), or the recent runs (neither; on="local" for this machine's, else your machines'). With cancel=true it cancels the run (or the job).

Permission: `runs:read`.

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| <span id="space_runs--cancel"></span>`cancel` | `boolean` |  | Cancel the run or the job. |
| <span id="space_runs--job"></span>`job` | `integer` |  | One job of the run. |
| <span id="space_runs--on"></span>`on` | `string` |  | Without run: local or auto (default). |
| <span id="space_runs--run"></span>`run` | `string` |  | A run id from space_run. |
| <span id="space_runs--state"></span>`state` | `string` |  | With run: only jobs in this state (queued, running, succeeded, failed, error, canceled). |
