`cua.auth()` signs in and reads the shared session. Cloud calls use it when no client credentials are configured.

Python programs usually use the high-level API instead: [`cua_sandbox.configure()`](/cua-sdk/reference/python/runtimes#configure).

## `Auth`

Sign-in and the shared session.

Returned by [`Cua.auth`](/cua-sdk/reference/cua#cua).

| Method | Description |
| --- | --- |
| [`access_token`](#authaccess_token) | A valid access token (refreshed when it expires within a minute, or when `force`). |
| [`begin_login`](#authbegin_login) | Starts a sign-in. |

### `LoginAttempt.wait`

Waits for the user, stores the session and returns who signed in.
Only the first call waits; later calls fail.

This device then registers with the relay (the one `cua` uses:
`CUA_RELAY_URL`, else this machine's host setup, else relay.cua.ai),
creating its device key on first use, so the fresh sign-in enrolls
or re-verifies it without an approval. That step is best effort and
never fails the sign-in.
