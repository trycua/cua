### `cua spaces egress`

Choose which destinations a Space may reach: block some, or block everything except a few. The machine the Space runs on enforces it, outside the guest (nothing in the guest, root included, can change it). Replaces the whole policy at once; `--clear` removes it. By IP address or CIDR (`all` is every address), not by hostname. DNS works only while the resolver the guest uses is not blocked.

.

Everything is allowed unless a rule says otherwise: every --deny entry blocks that destination, and every --allow entry is an exception that wins over a --deny. --allow alone blocks nothing. Loopback, replies to connections made to the Space and IPv6 neighbor discovery are never filtered. Containers (runc, gVisor), and QEMU and Firecracker VMs on Linux take a policy; macOS VMs, Apple Containerization, Cua Cloud and your own cloud accounts refuse one and say why.

```text output
cua spaces egress [OPTIONS] <SPACE>
```

| Argument | Type | Default | Description |
| --- | --- | --- | --- |
| `<SPACE>` | string | required | Space id or name. |

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| <span id="cua-spaces-egress--deny"></span>`--deny` | string |  | A destination to block (IPv4/IPv6 address, CIDR or `all`; repeat for more). Repeatable. |
| <span id="cua-spaces-egress--allow"></span>`--allow` | string |  | A destination that stays reachable where --deny blocks it (repeat for more). Repeatable. |
| <span id="cua-spaces-egress--clear"></span>`--clear` | boolean | `false` | Remove the policy. |

**Examples**

```bash test="cli-shape" id="ref-cua-spaces-egress"
# Block one network
cua spaces egress studio --deny 10.0.0.0/8

# Only 1.1.1.1 and one network stay reachable
cua spaces egress studio --deny all --allow 1.1.1.1 --allow 203.0.113.0/24

# Back to unrestricted
cua spaces egress studio --clear
```

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Success. |
| `1` | Failure, or `cua do` reported an error. |
| `2` | Invalid argument, or an ambiguous sandbox name (qualify it: `local:NAME`). |
| `3` | Not found: sandbox, window, skill or image (or an image not published yet). |
| `4` | Not supported, or not configured (for example no provider credentials). |
| `5` | No cua-spacesd answered, or a transport failure. |
| `6` | Unauthenticated or permission denied (by Cua or your cloud account). |
| `7` | Not enough free disk space (see `cua cache`). |
| `8` | No room on the machine: its VMs are at their memory or CPU limit, or it is low on memory. |
| `130` | Cancelled (Ctrl-C during a create): what it made was removed. |
