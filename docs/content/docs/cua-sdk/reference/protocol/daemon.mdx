The local `cua daemon` API (a Unix socket on the host, not cua-spacesd): sandbox lifecycle across locations; checkpoints of local sandboxes that new sandboxes fork from (`ForkSandbox`); local pools of ready sandboxes (`ApplyPool`, `ListPools`, `DeletePool`, claimed by a create that names one in `local_pool`); and the local runtimes (gVisor, runc, QEMU, Lume, Firecracker) and images it orchestrates. Spaces and the daemon's identity are on [Daemon: Spaces and service](/cua-sdk/reference/protocol/daemon-spaces).

Source: `libs/cua/proto/cua/daemon/v1/sandboxes.proto`, `libs/cua/proto/cua/daemon/v1/checkpoints.proto`, `libs/cua/proto/cua/daemon/v1/pools.proto`, `libs/cua/proto/cua/daemon/v1/runtime.proto`.

### SandboxService.CancelCreateSandbox

`/cua.daemon.v1.SandboxService/CancelCreateSandbox`, unary: [`CancelCreateSandboxRequest`](#cancelcreatesandboxrequest) to [`CancelCreateSandboxResponse`](#cancelcreatesandboxresponse).

Cancels a `CreateSandbox` of a named sandbox still running: the work
in flight stops (an image download, a boot) and what the
create made is deleted; a sandbox of that name that existed before is
never touched. Finished image downloads stay cached. Returns once the
clean-up is done. Idempotent: `cancelled` is false when no create of
that name was running. A `CreateSandbox` whose caller goes away (a
closed connection) is cleaned up the same way.
