# The Spaces contract

The Spaces tools that `cua mcp` / `cua daemon mcp` serve, with their input
schemas. `manifest.json` is **generated**. Edit
`../crates/cua-spaces-contract/src/lib.rs` and run:

```sh
cd .. && cargo run -p cua-spaces-contract --bin cua-spaces-contract-gen
```

`--check` fails when the checked-in file no longer matches the Rust, which is
what keeps it a contract rather than documentation.

## Fields beyond the Cua Driver shape

- **`providers`**: any of `cloud`, `local`, `direct` and `relay` (the
  location words of sandbox refs). `create_space` creates in `cloud` or
  `local` (its `on` argument); every other tool works on all four.
- **Space ids** are sandbox refs: `local:<name>`, `cloud:<name>`,
  `direct:<host:port>`, `relay:<machine-id>`. Legacy `space://…` ids still
  parse.
- **`metering`**: `free`, `metered`, or `cloud` (metered only when it creates
  in the cloud). Only `create_space` is not free, and only with `on: cloud`.
- **`sdk_symbol`**: the typed Swift path covering the tool, so a binding can
  diff its own surface against the contract instead of against prose.

`platforms` is the *operator's* OS. For the operator-display and hotspot
tools that is the axis that matters, because those act on the human's machine
rather than inside the Space.

## fixtures/transcript

The cross-language conformance set, generated by
`cargo run -p cua-spaces-transcript --bin cua-spaces-fixtures`:

- `casts/`: 7 asciinema v2 recordings of real Claude Code sessions, copied
  from the Swift golden suite so all three languages read one copy.
- `instants.json`: the 11 named instants. Adding one is a single edit in
  `conformance.rs` rather than three edits in three test suites.
- `frames/`: the expected `cua.transcript.frame/1` document for each: the
  rendered grid, down to cursor column and SGR run boundary.
- `jsonui/`: the expected `cua.transcript.jsonui/2` document for each: the
  structured reading of that grid, element by element, each with the
  provenance that says whether it was read off the screen or concluded from
  it. These are the eleven Swift goldens promoted to cross-language fixtures.

`cua.transcript.jsonui/2` differs from the `/1` that `libs/spaces-sdk-swift`
emits in exactly one way: `source.frameTime` (a float, in seconds) is
`source.frameTimeMs` (an integer), and `cast` and `instant` are added so a
fixture identifies itself. A float on the wire would make a three-language
byte comparison a test of three float formatters. A renamed key is a major
bump by the schema's own versioning rule, hence `/2`; every element type and
every body key is `/1` unchanged.

Do not edit a fixture by hand. `cargo test -p cua-spaces-transcript` re-derives
every one of them and will say so.
