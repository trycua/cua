## `cua share`

Share a link to a port, a file or a folder that opens on your other signed-in devices (never localhost): `cua share 3000`, `cua share ./report.html`, `cua share ls`, `cua share stop ID`.

```text output
cua share [OPTIONS] <TARGET>
       cua share <COMMAND>
```

| Argument | Type | Default | Description |
| --- | --- | --- | --- |
| `<TARGET>` | string | required | What to share: a port (`3000`), a port in a Space (`space:NAME:3000`), or a file or folder (`./report.html`, `./build/`). Paths are read-only; use `./ls` for a file called `ls`. |

| Flag | Short | Type | Default | Description |
| --- | --- | --- | --- | --- |
| <span id="cua-share--ttl"></span>`--ttl` |  | string |  | How long the share lasts (`10m`, `1h`, 60s to 24h). Public shares default to 1h; the others have no end unless you set one. |
| <span id="cua-share--name"></span>`--name` |  | string |  | A name for `cua share ls` (and `cua share stop NAME`). |
| <span id="cua-share--service"></span>`--service` |  | string |  | With --tcp: the game or service (`minecraft`), for a name people can type instead of the address. |
| <span id="cua-share--route"></span>`--route` |  | `auto` \| `host` \| `edge` \| `relay` |  | With --tcp: how people reach it. `auto` (default) takes the Space's own host in your cloud, else a small server in your linked cloud (a share edge), else Cua's relay, within `cua share settings`. |
| <span id="cua-share--allow"></span>`--allow` |  | string |  | With --tcp: only these addresses or CIDRs may connect (repeat it). Default: the settings' allowlist, usually anyone. Repeatable. |
| <span id="cua-share--team"></span>`--team` |  | boolean | `false` | Share with the members of your team. |
| <span id="cua-share--public"></span>`--public` |  | boolean | `false` | Anyone with the link can open it. Expires (default 1h, 60s to 24h). |
| <span id="cua-share--tcp"></span>`--tcp` |  | boolean | `false` | Share a raw TCP service in a Space (a game server, for example) at a public address instead of a link: anyone with the address can connect, for 24h unless --ttl says less. Needs --public and a port in a Space (inside a Space, a bare port is its own). An experiment: turn on Public TCP shares in Settings, Labs. |
| <span id="cua-share--check-host"></span>`--check-host` |  | boolean | `false` | With --tcp --service minecraft: drop connections that did not dial this share's address (scanners, stale addresses). |
| <span id="cua-share--yes"></span>`--yes` | `-y` | boolean | `false` | With --tcp: agree to the share edge's cost without asking (the first share through your cloud creates a small server there). |

**Examples**

```bash test="cli-shape" id="ref-cua-share"
# A dev server on this machine, for your own devices (phone included)
cua share 3000

# A port inside a Space
cua share space:dev:3000

# A report or a folder, read-only
cua share ./report.html
cua share ./build/

# Members of your team
cua share 3000 --team

# Anyone with the link, for an hour
cua share ./report.html --public --ttl 1h

# A game server in a Space, at a public address (Labs: Public TCP shares)
cua share space:mc:25565 --tcp --public --service minecraft

# The same from an agent inside the Space (its own port)
cua share 25565 --tcp --public --service minecraft

# Through your own cloud only, for two friends' addresses
cua share space:mc:25565 --tcp --public --route edge --allow 203.0.113.7 --allow 198.51.100.0/24

# A share an agent asked for, waiting for you
cua share approve share-1a2b3c4d5e6f

# Where public TCP shares go, the daily data cap and the default allowlist
cua share settings

# What is shared, and stop it
cua share ls
cua share stop share-1a2b3c4d5e6f
cua share stop all
```

### `cua share settings`

Where public TCP shares go, the daily data cap, the default allowlist and the approval rule; with no flags, shows them.

```text output
cua share settings [OPTIONS]
```

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| <span id="cua-share-settings--land"></span>`--land` | `auto` \| `only-my-cloud` \| `allow-relay` |  | `auto`, `only-my-cloud` or `allow-relay`. |
| <span id="cua-share-settings--relay"></span>`--relay` | `on` \| `off` |  | Whether Cua's relay may carry public TCP shares at all. |
| <span id="cua-share-settings--daily-cap"></span>`--daily-cap` | string |  | The most data public TCP shares move in a day (`2GB`, `500MB`, `off`). |
| <span id="cua-share-settings--allow"></span>`--allow` | string |  | The allowlist new shares start with (repeat it). Repeatable. |
| <span id="cua-share-settings--approve-agents"></span>`--approve-agents` | `on` \| `off` |  | Ask before an agent's share goes public (`on`, the default). |
| <span id="cua-share-settings--allow-anyone"></span>`--allow-anyone` | boolean | `false` | New shares are open to anyone (clears the allowlist). |
| <span id="cua-share-settings--remove-edge"></span>`--remove-edge` | boolean | `false` | Remove the share edge from your cloud now; its shares end. |

**Examples**

```bash test="cli-shape" id="ref-cua-share-settings"
# Show them
cua share settings

# Never through Cua: only your own cloud
cua share settings --land only-my-cloud

# A 5 GB daily data cap, or none
cua share settings --daily-cap 5GB
cua share settings --daily-cap off

# New shares only for these addresses
cua share settings --allow 203.0.113.0/24

# Remove the share edge from your cloud now
cua share settings --remove-edge
```

### `cua network set`

Change what a Space can reach. A child Space stays within its parent's unless `--widen`.

```text output
cua network set [OPTIONS] <SPACE>
```

| Argument | Type | Default | Description |
| --- | --- | --- | --- |
| `<SPACE>` | string | required | Space id or name. |

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| <span id="cua-network-set--network"></span>`--network` | string |  | `internet`, `none`, `localhost:<ports>` (or `localhost:all`), `lan`, `localhost+lan:<ports>` (both), `custom`, `custom:none` or `unprotected` (No protection). Left out: the preset it has (to change only `--via`). |
| <span id="cua-network-set--via"></span>`--via` | string |  | Where its internet traffic leaves: `internet` (its own network, the default), `this-computer` (this computer's network: the hotspot), `space:<name>` (a Space of its tree) or `socks5://host:port`. Its rules apply first; if the exit goes away, its internet stops (it never falls back). A child keeps its parent's. Left out: the exit it has. |
| <span id="cua-network-set--allow"></span>`--allow` | string |  | Allow this destination (IP, CIDR, or a name such as `pypi.org` or `*.github.com` on runtimes behind the Cua network gateway; repeat for more). Repeatable. |
| <span id="cua-network-set--deny"></span>`--deny` | string |  | Block this destination (IP, CIDR, `all`, or a name on runtimes behind the Cua network gateway; repeat for more). A deny wins over the Space's own tree: it blocks a member of the tree too. Repeatable. |
| <span id="cua-network-set--widen"></span>`--widen` | boolean | `false` | A child Space: let it reach more than its parent (recorded on the Space). |
| <span id="cua-network-set--tree"></span>`--tree` | boolean | `false` | Its child Spaces get the same settings (each within its parent's). |

**Examples**

```bash test="cli-shape" id="ref-cua-network-set"
# This computer's Postgres and dev server only
cua network set studio --network localhost:5432,3000

# Your local network too
cua network set studio --network lan

# Only these destinations
cua network set studio --network custom:none --allow 140.82.112.0/20

# Back to the default
cua network set studio --network internet

# Its internet traffic leaves through this computer (the hotspot)
cua network set studio --via this-computer

# ... or through another Space of its tree, or a SOCKS5 proxy
cua network set worker --via space:gateway
cua network set studio --via socks5://proxy.example:1080

# Its own network again
cua network set studio --via internet
```

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Success. |
| `1` | Failure, or `cua do` reported an error. |
| `2` | Invalid argument, or an ambiguous sandbox name (qualify it: `local:NAME`). |
| `3` | Not found: sandbox, window, skill or image (or an image not published yet). |
| `4` | Not supported, or not configured (for example no provider credentials). |
| `5` | No cua-spacesd answered, or a transport failure. |
| `6` | Unauthenticated or permission denied (by Cua or your cloud account). |
| `7` | Not enough free disk space (see `cua cache`). |
| `8` | No room on the machine: its VMs are at their memory or CPU limit, or it is low on memory. |
| `130` | Cancelled (Ctrl-C during a create): what it made was removed. |
