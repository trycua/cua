app in the background. By the end, the agent opens Calculator, computes 6 × 7,
and reports 42 from the app itself.

## Before you start

- macOS 14+, Windows 10/11, or an x86_64 Linux desktop (X11 or XWayland, with AT-SPI 2)
- An agent that supports MCP or skills, such as Claude Code or Codex
- A desktop calculator app. On Linux, use your distribution's, such as GNOME Calculator.

Run every step in the desktop session you want the agent to drive.

## 1. Install and start Cua Driver

No administrator access is needed. The installer picks the right path for your
platform.

<Tabs items={['macOS', 'Windows', 'Linux']}>
  <Tab value="macOS">

```bash test="cli-shape" id="cua-driver-permissions-grant"
/bin/bash -c "$(curl -fsSL https://cua.ai/driver/install.sh)"
cua-driver permissions grant
```

`permissions grant` starts the installed app by its exact path, so macOS
attributes the prompts to that copy of CuaDriver and the grant sticks to the driver.

macOS asks once for each permission. Neither prompt grants anything by
itself: both offer **Open System Settings**, not **Allow**.

![The macOS Accessibility Access prompt for CuaDriver, offering Open System Settings or Deny](https://github.com/user-attachments/assets/b7a5a0c0-f297-4249-81f9-ca42c6b6f8ba)

![The macOS Screen Recording prompt for CuaDriver, offering Open System Settings or Deny](https://github.com/user-attachments/assets/69efc964-a375-495e-8a27-400c9dd08e17)

**Open System Settings** adds CuaDriver to that permission's list, switched
off. Switching it on is what grants access.

![CuaDriver listed under Accessibility in System Settings with its toggle switched off](https://github.com/user-attachments/assets/d149fe5a-28cb-460c-8868-4eda80d540a4)

![CuaDriver listed under Screen & System Audio Recording in System Settings with its toggle switched off](https://github.com/user-attachments/assets/469308b5-84d7-4fd6-a580-e62925120337)

<Callout type="warn">
  Switch on both **Accessibility** and **Screen & System Audio Recording**. If you choose
  **Deny**, the driver cannot see or drive your desktop. macOS may offer to quit and reopen
  CuaDriver when you flip a toggle. Accept: the driver only picks up a changed grant after a full
  relaunch. If the daemon does not come back, run `cua-driver permissions grant` again.
</Callout>

macOS does not always show both prompts in one pass. Check what landed:

```bash test="cli-shape" id="cua-driver-permissions-status"
cua-driver permissions status
```

If one is still missing, run `cua-driver permissions grant` again.

  </Tab>
  <Tab value="Windows">

```powershell test="cli-shape" id="cua-driver-autostart-kick"
irm https://cua.ai/driver/install.ps1 | iex
cua-driver autostart kick
```

The installer tries to register Cua Driver to start at sign-in, and `kick`
starts that task now. If registration was skipped or failed, run
`cua-driver serve` in a terminal in your desktop session and leave it open. Use
a second terminal for the checks below. Over SSH, see
[Windows over SSH](/cua-driver/guides/vms-and-remote#windows-over-ssh).

  </Tab>
  <Tab value="Linux">

```bash test="cli-shape" id="cua-driver-serve"
/bin/bash -c "$(curl -fsSL https://cua.ai/driver/install.sh)"
cua-driver serve
```

Run it in a terminal inside the desktop session, so the driver can reach its
display and accessibility bus, and leave it open. Use a second terminal for the
checks below. On a minimal Debian or Ubuntu image, first run
`sudo apt install libxi6 at-spi2-core`.

On GNOME, also install the bundled WinRects helper (no `sudo` needed), then
log out and back in once so Shell loads it:

```bash skip="host-install"
~/.cua-driver/packages/current/wayland-helper/install.sh
gnome-extensions info winrects@cua   # State: ACTIVE
```

  </Tab>
</Tabs>

The daemon starts in the default `standard` permission mode, which is right for
this walkthrough. Before a real workload, read [Permissions](/cua-driver/guides/permissions)
to decide whether it should be `bounded`. If macOS grants look stale, see
[Troubleshoot](/cua-driver/guides/troubleshoot#reset-stale-macos-permissions).

## 2. Check that it sees your apps

Run these in a second terminal. First confirm the daemon is reachable. You
should see `Cua Driver daemon is running`:

```bash test="cli-shape" id="cua-driver-status"
cua-driver status
```

Then check the environment. Read the whole report, warnings included: a zero
exit code does not prove the desktop is ready.

```bash test="cli-shape" id="cua-driver-doctor"
cua-driver doctor
```

Then list the GUI apps the driver can reach:

```bash test="cli-shape" id="cua-driver-call"
cua-driver call list_apps
```

The list should include an app you recognize. An empty list means the driver
cannot reach the desktop: open Calculator in that session and retry, and fix
any permission or display error `doctor` reports before you go on.

## 3. Connect your agent

Pick one way in. A skill teaches the agent to run the Cua Driver CLI. An MCP
registration exposes Cua Driver as a tool server. `mcp-config` prints the
registration command, which you run, and installs the skill for that agent
(add `--no-skills` to skip it). It uses the paths on your machine, not the
example paths below.

To set up every agent on the machine at once (skill and MCP server), run
`curl -fsSL https://cua.ai/install.sh | sh -s -- --select cua-driver` instead.
It also installs the `cua` CLI.

<Tabs items={['Claude Code', 'Codex', 'Prime Agent', 'OpenClaw', 'Hermes', 'Other']}>
  <Tab value="Claude Code">

Install the Cua Driver skill:

```bash test="cli-shape" id="cua-driver-skills-install"
cua-driver skills install
cua-driver skills status
```

Confirm that the status lists a Claude Code skill link, then start a fresh
Claude Code session. If the link is missing, see
[Install the agent skill](/agents#install-the-agent-skill).

To use plain MCP instead of the skill, print the registration command:

```bash test="cli-shape" id="cua-driver-mcp-config-claude"
cua-driver mcp-config --client claude
```

```bash output
claude mcp add-json --scope user cua-computer-use '{"args":["mcp"],"command":"/Users/you/.local/bin/cua-driver"}'
```

  </Tab>
  <Tab value="Codex">

```bash test="cli-shape" id="cua-driver-mcp-config-codex"
cua-driver mcp-config --client codex
```

Run the command it prints, which uses the absolute path of the installed binary:

```bash output
codex mcp add cua-driver -- /Users/you/.local/bin/cua-driver mcp
```

Run `codex mcp list` to confirm the `cua-driver` entry. Start a fresh Codex
session and use `/mcp` to check that the server is active. See the
[official Codex MCP instructions](https://learn.chatgpt.com/docs/extend/mcp).

  </Tab>
  <Tab value="Prime Agent">

Install the skill pack. Prime Agent finds it in its own skill directory and
calls Cua Driver from its persistent IPython environment, so it needs no MCP
registration.

```bash test="cli-shape" id="cua-driver-skills-install-2"
cua-driver skills install
cua-driver skills status
```

Run `/reload` in Prime Agent or start a new session so the skill appears. Use
`/skill:cua-driver` to load it explicitly.

  </Tab>
  <Tab value="OpenClaw">

```bash test="cli-shape" id="cua-driver-mcp-config-openclaw"
cua-driver mcp-config --client openclaw
```

Run the command it prints:

```bash output
openclaw mcp set cua-driver '{"command":"/Users/you/.local/bin/cua-driver","args":["mcp"]}'
```

<Callout type="warn">
  On macOS, a server started this way by the gateway does not inherit OpenClaw.app's own
  Accessibility and Screen Recording grants. To let the host app own the grants, see
  [Expose MCP from a desktop app](/cua-driver/guides/use-the-sdk#expose-mcp-from-a-desktop-app).
</Callout>

  </Tab>
  <Tab value="Hermes">

Hermes has a built-in `computer_use` toolset. Turn it on for the CLI instead of
adding a second raw MCP server, then start a chat with it:

```bash skip="third-party-cli"
hermes tools enable computer_use --platform cli
hermes -t computer_use chat
```

If it cannot reach Cua Driver, run `hermes computer-use install`, then check
with `hermes computer-use doctor`.

  </Tab>
  <Tab value="Other">

For Cursor, Antigravity, OpenCode, Pi, a local model, or another harness, see
[Connect your agent](/agents).

  </Tab>
</Tabs>

## 4. Ask your agent

Start a fresh agent session and send this prompt. It asks the agent to read
the calculator's display after acting, so the agent checks the app instead of
answering the arithmetic from memory.

```text output
Using the Cua Driver skill, open the installed calculator app,
compute 6 × 7, and read the displayed result back from a fresh snapshot.
```

Name the setup you chose in place of "the Cua Driver skill":

| Your setup | Say |
| --- | --- |
| Claude Code or Prime Agent, with the skill | the Cua Driver skill |
| Claude Code, with MCP registration | the cua-computer-use MCP server |
| Codex or OpenClaw | the cua-driver MCP server |
| Hermes | the computer_use toolset |

The app name, the controls, and the steps differ by platform and calculator.
The agent finds them from fresh state, and element indices from another run
do not carry over. If no calculator is installed, install one from your
platform's app store or package manager, then send the prompt again.

## 5. Check the result

The calculator shows **42**, and the agent reports that value from its last
read of the app. A correct answer alone does not prove the agent operated the
app.

Your own window, keyboard focus, and pointer should have stayed where they
were. The moving cursor is the agent's overlay, not your pointer. Watch for
this yourself: do not infer it from the answer. Cua Driver delivers input in
the background where the operating system allows it, and a few cases still
need the foreground: some apps accept only foreground input, launching an app
can raise its window, and native Wayland depends on the compositor. See
[Platform mechanisms](/cua-driver/concepts/how-cua-driver-works#platform-mechanisms)
and [Known limits](/cua-driver/guides/troubleshoot#known-limits).

## Clean up

```bash test="cli-shape" id="cua-driver-stop"
cua-driver stop
```

## Approve macOS permissions on managed Macs, CI hosts and VMs

Step 1 needs someone at the Mac to approve two prompts: Accessibility and
Screen Recording. Use the first option that fits.

1. **Managed Macs:** push an MDM profile with a Privacy Preferences Policy
   Control (PPPC) payload for `com.trycua.driver`. It pre-approves
   Accessibility. macOS does not let MDM grant Screen Recording silently, so
   set `ScreenCapture` to `AllowStandardUserToSetSystemService`: a standard user
   can then switch CuaDriver on without an administrator password.
2. **Hosts you operate (dev boxes, CI hosts, VMs):** when you tell your agent in
   the task that it may approve Cua Driver's prompts on this host, it runs
   `cua-driver permissions grant` and clicks **Allow** through the host's own
   VNC or Screen Sharing server. It clicks only prompts that name CuaDriver,
   and it logs each approval.
3. **Everyone else:** run `cua-driver permissions grant` and click through the
   prompts yourself, as in step 1.

Your agent never approves a prompt for another app, never does this without your
explicit authorization in the task, and never does it on a machine you do not
own or run. Approvals survive signed updates, so you approve once per Mac. The Cua
Driver skill has the example profile, the VNC helper and the exact steps: see
[Install and approve permissions](https://github.com/trycua/cua/blob/main/libs/cua-driver/rust/Skills/cua-driver/MACOS.md#install-and-approve-permissions).
