The call behind `cua build`: each filesystem step is a pinned checkpoint, a rebuild runs only what changed, and `Spaces.fork(tag, name)` or `SpaceCreateOptions.build` starts a Space from the result. See [Build an image from a Dockerfile](/cua-sdk/guides/build-an-image).

## Build

Methods of [`Spaces`](/cua-sdk/reference/spaces#spaces).

### `Spaces.build`

Builds an image from a Dockerfile or steps in a Space, as pinned
layer checkpoints on this machine. Layers already built are reused (a
rebuild of the same recipe is a cache hit that runs nothing; a
changed step rebuilds from it on), and identical builds in flight
share one run. The result's `checkpoint` is a fork source:
`Spaces.fork(result.tag or result.checkpoint, name)` starts a Space
from it in well under a second, with the image's environment,
working directory and user. A failed step is an error that names
the step, its exit code and its last output; earlier layers stay
cached.

### `Spaces.delete_build`

Deletes a build: its tags and the layer checkpoints no other build
uses. `build` is a tag, a recipe key (or its first 12 characters) or
a checkpoint. Returns the checkpoints deleted. Spaces already made
from it keep running.

## `BuildOptions` record

Options for `Spaces.build` and `super.SpaceCreateOptions.build`.
Give the recipe as a `dockerfile` (text) or a `base` image; `steps` are
applied after it.

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `dockerfile` | `Option<String>` | `None` | Dockerfile text. One stage; the instructions `cua build` documents (multi-stage, heredocs, BuildKit flags and `ONBUILD` are refused, naming the line). |
| `context_dir` / `contextDir` | `Option<String>` | `None` | The build context: the directory `COPY` sources are relative to (`.dockerignore` applies). Default: none, and a `COPY` fails. |
| `base` | `Option<String>` | `None` | A base image, for a build made of `steps` alone: a Cua image, `ubuntu:<version>`, `debian:<version>` or `python:<version>`. |
| `steps` | [`Vec<BuildStep>`](#buildstep-enum) | `[]` | Steps, after the Dockerfile's. |
| `build_args` / `buildArgs` | `HashMap<String, String>` | `[:]` | Build arguments (`ARG` values). |
| `tag` | `Option<String>` | `None` | An alias for the result: `Spaces.fork`, `build:<tag>` images and `Spaces.create(build=...)` find the build by it. |
| `kind` | `Option<String>` | `None` | `vm` (default), `container` or `microvm`. |
| `on` | `Option<String>` | `None` | Where: `local` (default). A build's checkpoints stay on the machine that took them. |
| `cpus` | `Option<u32>` | `None` | vCPUs of the build's machine, and so of Spaces made from it (default 2). |
| `memory_mb` / `memoryMb` | `Option<u64>` | `None` | Memory in MiB (default 4096). |
| `headless` | `Option<bool>` | `None` | No desktop: only cua-spacesd runs (default true). |
| `no_cache` / `noCache` | `bool` | `false` | Build every layer again instead of using cached ones. |
| `step_timeout_ms` / `stepTimeoutMs` | `Option<u64>` | `None` | Budget for each step in milliseconds (default one hour). |

## `BuildStep` enum

One build step. Values are literal: a Dockerfile's `$VAR`s are expanded
by `BuildOptions.dockerfile`'s parser, not here. `Run` and `Copy`
steps run as the `User`, in the `Workdir` and with the `Env` set before
them.
