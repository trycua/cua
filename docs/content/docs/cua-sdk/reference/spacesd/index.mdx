`sandbox.spacesd()`, `space.spacesd()` (or `cua.spacesd(url, token)` for any spacesd) returns a `SpacesdClient`. It picks native gRPC or gRPC-Web, sends the token and chunks transfers. Processes are below; [files](/cua-sdk/reference/spacesd/files) and the [computer and media](/cua-sdk/reference/spacesd/computer) have their own pages.

Python programs usually use the high-level API instead: [`cua_sandbox` interfaces](/cua-sdk/reference/python/interfaces).

cua-spacesd is optional: images without it still boot and serve their declared services, and `sandbox.spacesd()` raises `SpacesdNotAvailable`. `capabilities()` reports what this spacesd supports (`has_feature(name)` checks one feature). `call_json(method, json)` reaches every `cua.env.v1` RPC of the [protocol](/cua-sdk/reference/protocol), including those without a typed method.

### `SpacesdClient.call_json`

Calls any unary `cua.env.v1` RPC with a proto3-JSON request and
returns the proto3-JSON response. `method` is the full path
(`/cua.env.v1.WindowsService/ListWindows`) or `Service/Method`.
Covers windows, accessibility, driver tools, teleport, tunnels and
every other RPC without a typed method.

`user` makes a file request (`FilesystemService` `Stat`, `ListDir`,
`MakeDir`, `Move`, `Remove`, `CreateWatcher`, `CreateSignedUrl`,
`BeginUpload`) act as that guest user: it sets the request's
`run_as` (in `header` for `BeginUpload`) and checks that the guest
agent supports acting as another user. Any other method refuses it,
and so does a request that already names a different `run_as`.

### `SpacesdClient.route`

Which way calls go now, in one line: `local <host:port>` (a Space on
this machine), `direct <address>`, `relay <relay URL>` (the relay's
HTTPS path), `mesh direct <ip:port> rtt <ms> ms` (end to end over the
mesh, straight to the machine: a LAN neighbour), `mesh relayed` or
`cloud`. A Space one of your own machines provides prefers the
direct path and falls back to the relay by itself (`CUA_MESH=off`
turns that off). A client made otherwise reports where its spacesd
runs (`local`, `cloud`, `direct`) and the endpoint it dials.

## Without cua-spacesd

Any OCI image is a full Space on the container and microVM kinds: when the image carries no cua-spacesd (`alpine:3.20`, `node:20`), Cua puts a static one into it and runs it beside the image's own command, so exec, files and ports work. Pass `spacesd=False` to run the image as it is. The sandboxes without cua-spacesd are those: the macOS 15 image (macOS 26 runs cua-spacesd) and a VM of an image that ships no Cua disk (use kind `container` or `microvm`, or `cua build` FROM a Cua image), so `sandbox.spacesd()` fails for them. A local Lume sandbox is still reachable: commands over `lume ssh`, screenshots and the display over the VM's VNC endpoint. `cua sb exec`, `cua sb screenshot` and `cua sb view` use the same calls. Other sandboxes fail with `Unsupported`.

Python programs usually use the high-level API instead: [`cua_sandbox` shell and screen](/cua-sdk/reference/python/interfaces).

## `GuestDisplay`

The guest display of a sandbox without cua-spacesd
(`Sandbox.guest_display`). An object, not a record, so no binding's
default string form (repr, str, description, toString, Debug) can show
the VNC password: `url()` is masked, and only the explicit
`url_with_password()` returns it.

Returned by [`Sandbox.guest_display`](#sandboxguest_display).

| Accessor | Returns | Description |
| --- | --- | --- |
| `open_command()` | `Vec<String>` | A host command that opens a viewer on it (`lume attach <vm>`); empty when there is none. It handles the password itself. |
| `url()` | `String` | The display URL (`vnc://HOST:PORT`) with any password masked as `****`. Safe to print and log. |
| `url_with_password()` | `String` | SENSITIVE: the display URL with the VNC password (`vnc://:PASSWORD@HOST:PORT`), for handing to a VNC client. Never print or log it. |
| `via()` | `String` | How the display is reached (`vnc`). |
