### `Spaces.cancel_create`

Cancels a create that is still running: `space` is the create's
`create_id`, the id the Space will have (`local:<name>`, carried by
every progress report) or its name. The work in flight stops (an
image download, a boot, a relay registration) and what the
create made is removed (its VM or container and disks, its relay
machine); nothing that existed before is touched.
Finished image downloads stay cached, so the next create resumes.
Returns once the clean-up is done; the create itself fails with
`Cancelled`. Idempotent: a second call says `not_creating`. Works
for a create another process runs, and one a daemon restart cut off.

## `SpaceCreateOptions` record

Options for `Spaces.create`: the same location / kind / runtime model
as sandboxes.

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `image` | `Option<String>` | `None` | Image (default: the canonical Linux image). `checkpoint:<name>` starts a fork of that checkpoint, on whichever of your machines holds it (`CheckpointSummary.host`): its disk, memory and processes, so no command, environment, services, GPU or disk size. |
| `on` | `Option<String>` | `None` | Where: `local` (free), a connected cloud account (`aws`, `gcp`, `modal`) or `host:<name>`. `None`: the user default (`default.on`, `CUA_DEFAULT_ON`, else `local`); for a `checkpoint:` image, where the checkpoint is. | `kind` | `Option<String>` | `None` | `auto` (default), `container` or `vm`. |
| `runtime` | `Option<String>` | `None` | `auto` (default) or an engine the location offers for the kind. |
| `name` | `Option<String>` | `None` | Name (default `space-<hex>`). |
| `cpus` | `Option<u32>` | `None` | vCPUs. Local default 2. |
| `memory_mb` / `memoryMb` | `Option<u64>` | `None` | Memory in MiB. Local default 4096. |
| `disk_gb` / `diskGb` | `Option<u32>` | `None` | Grow the VM's disk to this many GiB (local VMs; default: the image's size, never smaller). Lume grows the macOS APFS container before the first boot; Linux images grow their root partition at boot. Containers and cloud Spaces refuse it. |
| `timeout_ms` / `timeoutMs` | `Option<u64>` | `None` | Readiness budget (local; default 600 s). |
| `wait` | `Option<bool>` | `None` | Wait until ready (default true). |
| `reuse` | `bool` | `false` | Return a reachable registered Space in the same location with the requested services instead of creating one. |
| `command` | `Option<Vec<String>>` | `None` | Entrypoint override. |
| `env` | `HashMap<String, String>` | `[:]` | Guest environment. |
| `services` | `HashMap<String, u16>` | `[:]` | Named services (name → guest port), for example `{"mcp": 8765}`. |
| `spacesd` | `Option<bool>` | `None` | Whether the image runs cua-spacesd (default: yes for the canonical images; any other image gets a static one injected on a local container or microVM, so it is a full Space; `false` runs the image as it is). |
| `gpu` | `Option<String>` | `None` | A GPU option of the runtime the Space runs on (`Spaces.gpu_support`): `paravirtual` for a macOS VM on Lume (GPU acceleration, experimental), `virgl` (QEMU on Linux), `nvidia` (a runc container on Linux); `auto` picks the runtime's own. `None` (the default): no GPU. Kept with the Space. |
| `create_id` / `createId` | `Option<String>` | `None` | Your own key for this create (an app's pending row), for `Spaces.cancel_create` before the Space's id is known. |
| `durable` | `bool` | `false` | Keep the Space on your machines (`on` "auto"): when its machine goes away it is created again on another one, with the same name (its disk starts fresh). Needs the cua daemon of Cua Spaces and an account with machines that provide Spaces. |
| `profile` | `Option<String>` | `None` | A size profile: defaults for what is left unset. `"rollout"`: 1 vCPU, 1024 MiB and `headless` (a local VM gets no display hardware, so many more fit on one machine), for RL rollouts and agent episodes that mostly wait. `None` or `"default"`: 2 vCPUs, 4096 MiB. |
| `headless` | `Option<bool>` | `None` | A Space without a desktop: only cua-spacesd runs (exec, files, processes, MCP), with no display, window manager or audio. For shell and RL workloads it starts several times faster and fits many more per machine. `None`: what `profile` says (a desktop by default). |
| `forkable` | `Option<bool>` | `None` | A fork source (a "bake" Space): a local QEMU VM's guest RAM is a shared file, so its checkpoints (`Space.checkpoint`) take milliseconds and forks of them (`Space.fork`, `Spaces.fork`) share its pages. Other kinds ignore it. `None` (the default): not one. |
| `build` | [`Option<BuildOptions>`](/cua-sdk/reference/spaces/build#buildoptions-record) | `None` | Build an image first (cached when unchanged), then fork the result. `image` must be unset. |
| `volumes` | [`Vec<VolumeMount>`](/cua-sdk/reference/spaces/volume#volumemount-record) | `[]` | Named volumes of Cua Volume to mount in the Space (`Spaces.create_volume`): each appears at its `path`, read-write or read-only; the Space sees no other volume. Needs the Cua Volume (Cua Spaces) and a guest that can mount it; the create fails otherwise, naming what is missing. A fork mounts the same volumes. |
| `network` | `Option<String>` | `None` | Guest network: `default` (unset) gives outbound network; `none` gives none (QEMU VMs, here or on one of your machines; published ports and cua-spacesd still reach the guest). ## `EgressPolicy` record

Which destinations a Space may open connections to. Everything is
allowed unless a rule says otherwise: every `deny` entry blocks that
destination, every `allow` entry is an exception that wins over `deny`
(`deny: ["all"]` with `allow: ["1.1.1.1"]` leaves only 1.1.1.1
reachable), and an `allow` list with no `deny` blocks nothing. Entries
are IPv4/IPv6 addresses or CIDRs (`all` is `0.0.0.0/0` and `::/0`);
a hostname is refused (rules are by IP/CIDR). DNS works only while the
resolver the guest uses is not blocked (or is allowed): there is no
special case. Loopback, replies to connections made to the guest and
IPv6 neighbor discovery are never filtered.

The host the Space runs on enforces it, outside the guest, from the
guest's first instruction (`SpaceInfo.egress_enforced`): containers
(runc and gVisor) on the container engine's host, Firecracker and QEMU
VMs on Linux in a network namespace around the VM. Nothing in the
guest, root included, can change it. macOS VMs, Apple Containerization,
QEMU on macOS or Windows, Cua Cloud and your own cloud accounts refuse
a policy (`Unsupported`, saying why).

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `allow` | `Vec<String>` | `[]` | Destinations that stay reachable where `deny` blocks them. |
| `deny` | `Vec<String>` | `[]` | Destinations that are blocked. |
