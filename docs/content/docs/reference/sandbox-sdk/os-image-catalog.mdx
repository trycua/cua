This catalog covers Sandbox SDK image mappings, desktop container build targets,
and the linked guest-image recipes in this repository. It is not a list of every
OS accepted by a hypervisor or every image in a registry. A configured reference
does not prove that its tag is currently available or that its guest boots on
every host or Fleet deployment.

Registry here means a **VM or container image registry**, not a distribution's
package repository. Desktop environments, window managers, and display protocols
are separate properties: for example, Xfce is a desktop environment, Xfwm4 is its
window manager, and X11 is its window system.

## Additional container build targets

These are repository publication targets on **Docker Hub**, not interchangeable
Fleet guest disks. Publication workflows alone do not establish current tag
availability. Use an existing version tag or digest from the registry.

| Image repository | Guest distribution / OS | Desktop or role | Source |
| --- | --- | --- | --- |
| `docker.io/trycua/xfce-cua` | Debian Bookworm | Application-neutral Xfce / Xfwm4 / X11 desktop with Cua Driver | `libs/xfce-cua/Dockerfile` |
| `docker.io/trycua/cua-xfce` | Debian Bookworm, KiCad 9 base | Xfce / Xfwm4 / X11; KiCad-specific, amd64 build target | `libs/xfce/Dockerfile` |
| `docker.io/trycua/cua-ubuntu` | Ubuntu 22.04 Jammy Kasm base | Desktop inherited from the Kasm base; KasmVNC | `libs/kasm/Dockerfile` |
| `docker.io/trycua/cua-qemu-linux` | Ubuntu guest supplied by the QEMU base | Docker-wrapped QEMU launcher, not a desktop container | `libs/qemu-docker/linux/Dockerfile` |
| `docker.io/trycua/cua-qemu-windows` | Windows; version depends on runtime configuration | Docker-wrapped QEMU launcher | `libs/qemu-docker/windows/Dockerfile` |
| `docker.io/trycua/cua-qemu-android` | Android 11 (`budtmo/docker-android:emulator_11.0` base) | Android emulator container; amd64 build target | `libs/qemu-docker/android/Dockerfile` |

The SDK's QEMU container selectors use `:latest` for the three `cua-qemu-*`
repositories. Their container base OS is not necessarily the guest OS. The Android
container's Android 11 base is distinct from the SDK constructor's Android 14
value; do not infer an emulator version from that constructor alone.

## Desktop coverage is not image availability

GNOME/Mutter, KDE Plasma/KWin, and Sway/wlroots appear in Cua Driver's platform
documentation. That does **not** establish corresponding Sandbox image registry
entries. No Sandbox mapping for those desktops is listed in the sources below.
Likewise, a Hyprland image is not proof that every Driver action works on Hyprland.

Consult [Cua Driver platform support](/reference/cua-driver/platform-support)
for compositor-specific capabilities and limitations. To use a different desktop
or distribution, prepare a compatible guest image rather than guessing an image
name from the window manager's name.

## Registry lookup and source of truth

| Registry | Catalog entries | Browse |
| --- | --- | --- |
| Amazon ECR Public | Ubuntu and Windows Fleet disks, Ubuntu Docker selector, Omarchy recipe, NixOS StumpWM and XFCE candidates | [Public gallery](https://gallery.ecr.aws/k5j5w0x5) |
| GitHub Container Registry | macOS Sequoia and Tahoe Lume images | [Cua packages](https://github.com/orgs/trycua/packages) |
| Docker Hub | Desktop container and QEMU launcher publication targets | [Cua repositories](https://hub.docker.com/u/trycua) |

Use fully qualified references to avoid registry ambiguity. In particular, the
SDK's registry parser defaults short references to GHCR, while Docker resolves
ordinary short container names through Docker Hub. Set `os_type` and `kind`
explicitly for a registry VM; a Windows disk needs `os_type='windows', kind='vm'`.
