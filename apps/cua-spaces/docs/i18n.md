# Translating UI strings

The shared web UI uses i18next with ICU messages. Only English (`en`) is bundled for now; translations are generated in CI later, so edit `en` only.

## Add a string

1. Pick the namespace for the area (`common`, `onboarding`, `spaces`, `sharing`, `billing`, `settings`, `teleport`, `agents`, `devices`, `installer`, `errors`) and add the key to `src/i18n/locales/en/<ns>.json`.
2. Name it `<area>.<screen_or_component>.<element>` in lower snake case, by role, never by its English text: `sharing.sheet.invite_button`.
3. Use it:

```tsx
import { useT } from "../i18n";

const t = useT("sharing");
<button title={t("sharing.sheet.invite_button_hint")}>{t("sharing.sheet.invite_button")}</button>;
```

Outside React, use `t("sharing:sheet.invite_button")` from `src/i18n`.

## Rules

- Write the whole sentence in one key. Never concatenate pieces.
- Variables and plurals use ICU: `"{count, plural, one {# Space} other {# Spaces}}"`, called as `t("spaces.list.count", { count })`.
- Rust returns error codes and variables, never English. Map them to `errors` keys in the UI.
- Keep product names (Cua, Spaces, Cua Driver, Teams, Pro) as they are.

## Guardrail

`src/i18n/noHardcodedStrings.test.ts` fails on JSX text and on `title`, `aria-label`, `placeholder`, `alt` and `label` string literals in the files listed in `MIGRATED`. When you finish extracting a file or directory (paths relative to `src/`), add it to that list in the same PR.
