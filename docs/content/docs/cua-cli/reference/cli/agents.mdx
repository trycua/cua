### `cua agent add`

Add an agent: a name, a harness and a Space.

.

With PROMPT it starts at once. --daily, --every or --weekly schedule PROMPT instead; --once runs PROMPT as a one-off task; --durable keeps it running through crashes.

```text output
cua agent add [OPTIONS] --harness <HARNESS> <NAME> [PROMPT]
```

| Argument | Type | Default | Description |
| --- | --- | --- | --- |
| `<NAME>` | string | required | The agent's name: 1-63 of a-z, 0-9, `.`, `_`, `-`. |
| `<PROMPT>` | string | optional | What it starts on: a first message, a scheduled task (with --daily/--every/--weekly) or the task (--once, --durable). |

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| <span id="cua-agent-add--harness"></span>`--harness` | string | required | Harness id (`cua agent harnesses`). |
| <span id="cua-agent-add--in"></span>`--in` | string |  | The Space it works in (with --durable: a durable Space by name; default `auto`, none). |
| <span id="cua-agent-add--model"></span>`--model` | string |  |  |
| <span id="cua-agent-add--base-url"></span>`--base-url` | string |  |  |
| <span id="cua-agent-add--env-from-host"></span>`--env-from-host` | string |  | Provider key variable to forward at each start. Repeatable. |
| <span id="cua-agent-add--on"></span>`--on` | string |  | With --durable: the machine the driver runs on (`auto`, or a machine's name; default: this machine). |
| <span id="cua-agent-add--every"></span>`--every` | integer |  | Schedule PROMPT every N minutes. |
| <span id="cua-agent-add--daily"></span>`--daily` | string |  | Schedule PROMPT every day at HH:MM. |
| <span id="cua-agent-add--weekly"></span>`--weekly` | string |  | Schedule PROMPT every week, `mon 09:00`. |
| <span id="cua-agent-add--title"></span>`--title` | string |  | The schedule's title (default: the agent's name). |
| <span id="cua-agent-add--once"></span>`--once` | boolean | `false` | A one-off task: run PROMPT and stop when it is answered (no name kept, no memory). |
| <span id="cua-agent-add--durable"></span>`--durable` | boolean | `false` | Keep it running through crashes: your machines' coordinator starts it again (a durable session, `cua agent run --durable`). |

**Examples**

```bash test="cli-shape" id="ref-cua-agent-add"
cua agent add ada --harness hermes --in local:dev --env-from-host OPENAI_API_KEY
cua agent add ada --harness claude-code --in local:dev "summarize the repo"
cua agent add ada --harness claude-code --in local:dev --daily 08:00 "plan the day"
cua agent add fix-1 --harness claude-code --in local:dev --once "fix the failing test"
cua agent add nightly --harness claude-code --durable --on auto "refactor the parser"
```

| <span id="cua-agent-run--branch"></span>`--branch` |  | string |  |  |

| <span id="cua-agent-run--mcp"></span>`--mcp` |  | string |  | An MCP server for the agent: NAME=URL (HTTP, as reachable inside the sandbox) or NAME=cmd:COMMAND ARGS... (stdio, run in the sandbox). Repeatable. |

| <span id="cua-agent-run--max-attempts"></span>`--max-attempts` |  | integer |  | With --durable: drives allowed in total before the session fails (default 5). |
| <span id="cua-agent-run--stall-secs"></span>`--stall-secs` |  | integer |  | With --durable: seconds the driver may write no output before it counts as wedged, is cancelled and started again (default 120; 0: never). Drivers print a heartbeat every quarter of it. |
| <span id="cua-agent-run--name"></span>`--name` |  | string |  | With --durable: the session's name (default: generated). |
| <span id="cua-agent-run--local"></span>`--local` |  | boolean | `false` | Look NAME up among local sandboxes only (same as `local:NAME`). |

| <span id="cua-agent-run--no-skills"></span>`--no-skills` |  | boolean | `false` | Do not copy the cua skills into the harness. |
| <span id="cua-agent-run--exit-when-idle"></span>`--exit-when-idle` |  | boolean | `false` | Stop (resumably) once the prompt is answered. |
| <span id="cua-agent-run--follow"></span>`--follow` | `-f` | boolean | `false` | Stream events until the turn ends. |
| <span id="cua-agent-run--durable"></span>`--durable` |  | boolean | `false` | Keep the agent alive across a lost driver or machine: your machines' coordinator starts it again (a higher epoch each time, with backoff and a cap). SANDBOX is then a durable Space by name, or `auto` for none. |

| Flag | Type | Default | Env var | Description |
| --- | --- | --- | --- | --- |
| <span id="cua-mcp--permissions"></span>`--permissions` | string |  | `CUA_MCP_PERMISSIONS` | Comma-separated permissions or groups (default: all). |
| <span id="cua-mcp--sandbox"></span>`--sandbox` | string |  | `CUA_SANDBOX` | Default sandbox for computer tools. |
| <span id="cua-mcp--member"></span>`--member` | string |  |  | Serve only the Space thread tools (thread_join, thread_inbox, thread_read, thread_post, agent_members) as the agent this computer joined with `cua join` (`<space>/<handle>`). Its key stays in the keychain. |

**Examples**

```bash test="cli-shape" id="ref-cua-mcp"
# Serve every tool over stdio (what MCP clients launch)
cua mcp

# Read-only sandbox tools, computer tools on the sandbox dev
cua mcp --permissions sandbox:readonly,computer:all --sandbox dev

# An agent that joined a Space with cua join: its thread tools only
cua mcp --member ubuntu-build/codex
```

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Success. |
| `1` | Failure, or `cua do` reported an error. |
| `2` | Invalid argument, or an ambiguous sandbox name (qualify it: `local:NAME`). |
| `3` | Not found: sandbox, window, skill or image (or an image not published yet). |
| `4` | Not supported, or not configured (for example no provider credentials). |
| `5` | No cua-spacesd answered, or a transport failure. |
| `6` | Unauthenticated or permission denied (by Cua or your cloud account). |
| `7` | Not enough free disk space (see `cua cache`). |
| `8` | No room on the machine: its VMs are at their memory or CPU limit, or it is low on memory. |
| `130` | Cancelled (Ctrl-C during a create): what it made was removed. |
