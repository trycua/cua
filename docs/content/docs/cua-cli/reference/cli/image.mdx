### `cua images release`

Run an image's release pipeline (its release.json): build, doctor lanes, content digest, save; with --publish push, publish pins and verify; with --promote move the floating tags. The same command runs locally and in CI.

Phases: prepare, build, gate (doctor lanes), stage, push, publish, verify,
promote. Push refuses unless every required gate passed (this run, or a
state-*.json merged from other jobs in &lt;work&gt;/evidence). Evidence, logs and
the summary go to &lt;work&gt;/evidence (a plain directory CI uploads as-is).

```text output
cua images release [OPTIONS] <DIR>
```

| Argument | Type | Default | Description |
| --- | --- | --- | --- |
| `<DIR>` | path | required | Image directory with a release.json. |

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| <span id="cua-images-release--tier"></span>`--tier` | string |  | Tier (`slim`, `full`) for images that have tiers. |
| <span id="cua-images-release--arch"></span>`--arch` | string |  | Arches, comma separated (default: release.json `arches`). Repeatable. |
| <span id="cua-images-release--stamp"></span>`--stamp` | string |  | Pin stamp `<yyyymmdd>-<sha7>` (default: today and git HEAD). |
| <span id="cua-images-release--work"></span>`--work` | path |  | Work directory (default: $CUA_RELEASE_WORK, else under the cua build cache, which `cua cache prune` manages). |
| <span id="cua-images-release--steps"></span>`--steps` | string |  | Only these steps: phase names or step-id prefixes (comma separated). Repeatable. |
| <span id="cua-images-release--from"></span>`--from` | string |  | Rerun from this phase or step; the steps before it must have passed. |
| <span id="cua-images-release--var"></span>`--var` | string |  | Variable KEY=VALUE for release.json templates (repeatable). |
| <span id="cua-images-release--assume"></span>`--assume` | string |  | Treat a host capability as present (`kvm`) or absent (`!runsc`). Repeatable. |
| <span id="cua-images-release--scope"></span>`--scope` | string |  | This run's state file name, state-&lt;scope&gt;.json (default: the arches); CI jobs sharing an evidence directory use distinct scopes. |
| <span id="cua-images-release--resume"></span>`--resume` | boolean | `false` | Skip steps that passed with the same inputs and whose outputs exist. |
| <span id="cua-images-release--dry-run"></span>`--dry-run` | boolean | `false` | Print the plan; run nothing. |
| <span id="cua-images-release--publish"></span>`--publish` | boolean | `false` | Also push, publish immutable pins and verify them. |
| <span id="cua-images-release--promote"></span>`--promote` | boolean | `false` | Also move the floating tags to the pins. |

**Examples**

```bash test="cli-shape" id="ref-cua-images-release"
# Plan only
cua images release libs/images/linux --tier slim --dry-run

# Build and doctor amd64 locally; resume after a failure
cua images release libs/images/linux --tier slim --arch amd64 --resume

# Rerun from the doctor lanes (the build must have passed)
cua images release libs/images/linux --tier slim --from gate

# One CI job's slice
cua images release libs/images/linux --tier full --arch arm64 --steps build,gate,stage --work release

# Publish and promote (the gates must have passed)
cua images release libs/images/omarchy --publish --promote --resume
```

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Success. |
| `1` | Failure, or `cua do` reported an error. |
| `2` | Invalid argument, or an ambiguous sandbox name (qualify it: `local:NAME`, `cloud:NAME`). |
| `3` | Not found: sandbox, window, skill or image (or an image not published yet). |
| `4` | Not supported, or not configured (for example no Fleet credentials). |
| `5` | No cua-spacesd answered, or a transport failure. |
| `6` | Unauthenticated or permission denied (by Cua, Fleet or your cloud account). |
| `7` | Not enough free disk space (see `cua cache`). |
| `130` | Cancelled (Ctrl-C during a create): what it made was removed. |
