## `cua run`

Run a Python function on your pool: `FILE::FN`, decorated with `@app.function(...)` (the `cua` jobs shim). Each member runs in a Space (a macOS VM with GPU on a Mac, the computer's own Space on a dedicated host, a container elsewhere); a lost computer re-places the gang and the job resumes from its checkpoints. Rank 0's result is saved in ./cua-runs/&lt;run&gt;/.

```text output
cua run [OPTIONS] [TARGET] [-- <COMMAND>...]
```

| Argument | Type | Default | Description |
| --- | --- | --- | --- |
| `<TARGET>` | string | optional | `FILE::FN`: a function decorated with `@app.function(...)` in FILE. Or leave it out and give a command after `--`. |
| `<COMMAND>...` | string | optional | A command to run in a Space instead of `FILE::FN` (`cua run -- CMD ARGS...`); the current directory goes with it like FILE's does. Repeatable. |

| Flag | Short | Type | Default | Description |
| --- | --- | --- | --- | --- |
| <span id="cua-run--compat"></span>`--compat` |  | string |  | Give the command another provider's sandbox API on Cua Spaces: `e2b`, `daytona` or `modal`. Its SDK finds the gateway in the environment (E2B_API_URL, E2B_API_KEY, ...; DAYTONA_API_URL, DAYTONA_API_KEY; MODAL_SERVER_URL, MODAL_TOKEN_ID, MODAL_TOKEN_SECRET) and needs no code change; the sandboxes it makes are Cua Spaces on your pool. |
| <span id="cua-run--kind"></span>`--kind` |  | string |  | The command's Space kind (`container`, `vm`, `microvm`; default: the host's pick). Command form only. |
| <span id="cua-run--image"></span>`--image` |  | string |  | The command's Space image (default: the host's). Command form only. |
| <span id="cua-run--nodes"></span>`--nodes` |  | string |  | Members of the gang, `N` or `MIN:MAX` (default: the decorator's). |
| <span id="cua-run--on"></span>`--on` |  | string |  | Where: `local` (this machine; the default for a command), `auto` (any of your hosts) or `host:NAME` (default for a function: the decorator's). |
| <span id="cua-run--accelerator"></span>`--accelerator` |  | string |  | `gpu` (any), `apple`, `nvidia`, or `none` (default: the decorator's). |
| <span id="cua-run--retries"></span>`--retries` |  | integer |  | Times the gang is placed again after a failure or a lost computer (default: the decorator's). |
| <span id="cua-run--cpus"></span>`--cpus` |  | number | `2` | CPUs reserved for each member. |
| <span id="cua-run--memory"></span>`--memory` |  | integer | `4096` | Memory reserved for each member, in MiB. |
| <span id="cua-run--env"></span>`--env` | `-e` | string |  | `KEY=VALUE` for every member's environment (over the decorator's `env=`), or `KEY` alone for this shell's value (secrets: never printed). Repeatable. |
| <span id="cua-run--id"></span>`--id` |  | string |  | The run's id (default: a new one). |
| <span id="cua-run--detach"></span>`--detach` |  | boolean | `false` | Submit, print the run's id and return. |

```bash test="cli-shape" id="ref-cua-run"
cua run train.py::finetune --nodes 1:2 --accelerator gpu
cua run train.py::finetune --on host:aws-1 --detach
```

### `cua compat serve`

Serve a provider's wire protocol from Cua Spaces until stopped.

```text output
cua compat serve [OPTIONS]
```

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| <span id="cua-compat-serve--provider"></span>`--provider` | string | `e2b` | Provider whose SDK clients use (`e2b`, `daytona`, `modal`). |
| <span id="cua-compat-serve--listen"></span>`--listen` | string |  | API (and envd) listen address. Loopback by default. |
| <span id="cua-compat-serve--host-port"></span>`--host-port` | integer |  | Port of the `<port>-<id>.<domain>` host router (TLS and plain HTTP). |
| <span id="cua-compat-serve--on"></span>`--on` | string |  | Where new Spaces run (default: the core default, this machine; `auto`: least-loaded machine of your pool; `host:<machine>`). |
| <span id="cua-compat-serve--kind"></span>`--kind` | string |  | Space kind (`vm`: Linux on QEMU/HVF or KVM; `container`; `microvm`). Default: `vm` where this machine can run one, else `container`. |
| <span id="cua-compat-serve--image"></span>`--image` | string |  | Image for the provider's base template (default: the canonical Linux image). |
| <span id="cua-compat-serve--cpus"></span>`--cpus` | integer |  | vCPUs per Space. |
| <span id="cua-compat-serve--memory-mb"></span>`--memory-mb` | integer |  | Memory per Space (MiB). |
| <span id="cua-compat-serve--overlay"></span>`--overlay` | string |  | Inject a freshly built binary into every new sandbox, `NAME=PATH[:GUEST_PATH]` (as `cua sandbox create --overlay`), for trying a guest agent that no image carries yet. Repeatable. |
| <span id="cua-compat-serve--default-user"></span>`--default-user` | string |  | The guest user for the provider's default user (default: the provider's own: `user` for E2B, `daytona` for Daytona, `root` for Modal). |
| <span id="cua-compat-serve--no-warm"></span>`--no-warm` | boolean | `false` | Do not make a first sandbox before serving. By default `serve` pulls the image and boots one default sandbox (then deletes it) and only then prints the `Clients export` line, so the first create of a separate client program cannot outlast the SDK's request timeout. |
| <span id="cua-compat-serve--no-create-user"></span>`--no-create-user` | boolean | `false` | Do not create the default user in images that lack it. |

**Examples**

```bash test="cli-shape" id="ref-cua-compat-serve"
cua compat serve --provider e2b
cua compat serve --provider daytona --on host:mac-studio --kind vm
cua compat serve --provider modal
cua compat serve --provider e2b --overlay cua-spacesd=./target/debug/cua-spacesd
```

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Success. |
| `1` | Failure, or `cua do` reported an error. |
| `2` | Invalid argument, or an ambiguous sandbox name (qualify it: `local:NAME`). |
| `3` | Not found: sandbox, window, skill or image (or an image not published yet). |
| `4` | Not supported, or not configured (for example no provider credentials). |
| `5` | No cua-spacesd answered, or a transport failure. |
| `6` | Unauthenticated or permission denied (by Cua or your cloud account). |
| `7` | Not enough free disk space (see `cua cache`). |
| `8` | No room on the machine: its VMs are at their memory or CPU limit, or it is low on memory. |
| `130` | Cancelled (Ctrl-C during a create): what it made was removed. |
