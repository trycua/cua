Checkpoints a host holds and copying them to your other machines: a manifest of files by SHA-256, read grants, resumable LAN copies with verification, and a fallback copy in S3 or a shared folder. The host's cua-spacesd forwards each call to its cua daemon.

Source: `libs/cua/proto/cua/env/v1/snapshots.proto`.

## HostSnapshotsService

`cua.env.v1.HostSnapshotsService`

Snapshots a host holds, and copying them between your machines.

A snapshot here is a local checkpoint (`cua.daemon.v1.Checkpoint`): a
sandbox's saved memory and disk that forks start from. Checkpoints are
kept on the machine that took them. To fork one on another machine of
the pool, that machine first gets a copy:

- The machine that has it describes it as a manifest: every file (the
  memory stream, the RAM file, the disk layers and their backing chain,
  UEFI variables, the guest token) by SHA-256 and size. The manifest's
  own SHA-256 is the snapshot's digest. It grants read access to those
  files for a short time (`ExportHostSnapshot`).
- The machine that needs it fetches each file it does not have yet,
  straight from that machine over the LAN (HTTP range requests, so a
  transfer that stopped resumes where it stopped), checks every file's
  SHA-256, and only then makes it a checkpoint of its own
  (`PullHostSnapshot`). Files are kept by content, so files that several
  snapshots share (a base disk) are copied once.
- When that machine cannot be reached, the files come from a copy
  published to your S3 bucket or Cua Volume (`PublishHostSnapshot`).

A checkpoint of a Space that a host provides is taken on that host
(`CreateHostSnapshot`), where the Space runs, and stays there: forks of
it start there, or on another machine after a copy. `DeleteHostSnapshot`
deletes one the host holds.

A host serves this service to the same callers as `HostSpacesService`
(the owner, its editors, and the env token holder of a direct host),
through its cua-spacesd, which forwards each call to the host's cua
daemon.

`/cua.env.v1.HostSnapshotsService/ExportHostSnapshot`, unary: [`ExportHostSnapshotRequest`](#exporthostsnapshotrequest) to [`ExportHostSnapshotResponse`](#exporthostsnapshotresponse).

### HostSnapshotsService.PullHostSnapshot

`/cua.env.v1.HostSnapshotsService/PullHostSnapshot`, server stream: [`PullHostSnapshotRequest`](#pullhostsnapshotrequest) to [`PullHostSnapshotResponse`](#pullhostsnapshotresponse).

Copies a snapshot to this host from another host (or the fallback),
streaming progress, and adds it as a checkpoint once every file is
verified. A snapshot this host already holds with the same digest is
not copied again.

### HostSnapshotsService.PublishHostSnapshot

`/cua.env.v1.HostSnapshotsService/PublishHostSnapshot`, server stream: [`PublishHostSnapshotRequest`](#publishhostsnapshotrequest) to [`PublishHostSnapshotResponse`](#publishhostsnapshotresponse).

Uploads a snapshot this host holds to the fallback store (S3 or Cua
Volume), streaming progress. Files already there are not uploaded
again.

### HostSnapshotsService.CreateHostSnapshot

`/cua.env.v1.HostSnapshotsService/CreateHostSnapshot`, unary: [`CreateHostSnapshotRequest`](#createhostsnapshotrequest) to [`CreateHostSnapshotResponse`](#createhostsnapshotresponse).

Checkpoints a Space this host provides (`CheckpointSandbox` on the
host): it keeps running. The owner checkpoints any; another account
only the Spaces it created. Fails with `NOT_FOUND` when the host does
not provide that Space, and `INVALID_ARGUMENT` when the name is taken.

### HostSnapshotsService.DeleteHostSnapshot

`/cua.env.v1.HostSnapshotsService/DeleteHostSnapshot`, unary: [`DeleteHostSnapshotRequest`](#deletehostsnapshotrequest) to [`DeleteHostSnapshotResponse`](#deletehostsnapshotresponse).

Deletes a checkpoint this host holds (forks made from it keep
running). The owner deletes any; another account only the ones it
took here. A pinned checkpoint is refused until it is unpinned.
Fails with `NOT_FOUND` when the host does not hold it.
