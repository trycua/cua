**Examples**

```bash test="cli-shape" id="ref-cua-sandbox-create"
# A Linux desktop on this computer (a gVisor container)
cua sb create linux --name dev

# A web server container, ready when its HTTP service answers
cua sb create python:3.12-slim --service web=8000 --wait http:web/ -- python -m http.server 8000

# The same Linux image as a VM
cua sb create linux --kind vm --name dev
```

### `cua sandbox checkpoint`

Save a local sandbox's state as a named checkpoint: its memory and disk on every kind (a gVisor container, a QEMU or Lume VM, a microVM; it keeps running), the filesystem where an engine cannot save memory. `cua sb fork` starts new sandboxes from it; forks of a QEMU checkpoint share its RAM copy-on-write (and a `--forkable` VM's checkpoints take milliseconds).

```text output
cua sandbox checkpoint [OPTIONS] <NAME> <CHECKPOINT>
```

| Argument | Type | Default | Description |
| --- | --- | --- | --- |
| `<NAME>` | string | required | Sandbox name or ref (`local:NAME`), or a Space another machine of yours provides (its name or id): that machine takes the checkpoint and keeps it. |
| `<CHECKPOINT>` | string | required | The checkpoint's name. |

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| <span id="cua-sandbox-checkpoint--pin"></span>`--pin` | boolean | `false` | Pin it: `cua sb checkpoints rm` and `prune` leave it until `cua sb checkpoints unpin`. |
| <span id="cua-sandbox-checkpoint--local"></span>`--local` | boolean | `false` | Look NAME up among local sandboxes only (same as `local:NAME`). |
| <span id="cua-sandbox-checkpoint--json"></span>`--json` | boolean | `false` | Machine-readable output. |

**Examples**

```bash test="cli-shape" id="ref-cua-sandbox-checkpoint"
cua sb checkpoint dev before-upgrade
cua sb fork before-upgrade dev-2

# A world to fork many times: kept until unpinned
cua sb create linux --kind vm --forkable --name bake
cua sb checkpoint bake world --pin
cua sb fork world agent-1

# A Space another machine of yours provides is checkpointed there
cua spaces create linux --kind vm --on host:kvm-a --name src
cua sb checkpoint src world
cua spaces create checkpoint:world --name agent-2
```

### `cua sandbox fork-many`

Fork a checkpoint many times at once, on this machine or across your machines, printing each fork as soon as it is ready (or failed). A group's forks (`--group-size`) go to one machine, so they share the checkpoint's memory there; groups spread over the least-loaded machines, the checkpoint is copied (and verified) to a machine that lacks it, and forks of a machine that fails are placed again.

```text output
cua sandbox fork-many [OPTIONS] [SOURCE]
```

| Argument | Type | Default | Description |
| --- | --- | --- | --- |
| `<SOURCE>` | string | optional | The checkpoint (or local sandbox) to fork. |

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| <span id="cua-sandbox-fork-many--count"></span>`--count` | integer | `1` | How many forks of SOURCE. |
| <span id="cua-sandbox-fork-many--group-size"></span>`--group-size` | integer | `0` | Forks per group (0: all in one group). |
| <span id="cua-sandbox-fork-many--group"></span>`--group` | string |  | A group `CHECKPOINT=COUNT` (repeatable), instead of SOURCE. |
| <span id="cua-sandbox-fork-many--on"></span>`--on` | string |  | Where: `local` (default), `auto` (your machines that provide Spaces, this one included), or `host:<machine>`. |
| <span id="cua-sandbox-fork-many--parallel"></span>`--parallel` | integer | `0` | Forks started at once per machine (0: 4). |
| <span id="cua-sandbox-fork-many--prefix"></span>`--prefix` | string |  | Names are `<prefix>-<n>`. |
| <span id="cua-sandbox-fork-many--fallback-dir"></span>`--fallback-dir` | string |  | A folder every machine mounts (your Cua Volume) to fetch checkpoints from when their machine is away. |
| <span id="cua-sandbox-fork-many--fallback-s3"></span>`--fallback-s3` | string |  | An S3 `bucket[/prefix]` to fetch checkpoints from when their machine is away (each machine's AWS credentials). |
| <span id="cua-sandbox-fork-many--fallback-region"></span>`--fallback-region` | string |  | The fallback bucket's region. |
| <span id="cua-sandbox-fork-many--cpus"></span>`--cpus` | integer | `0` | vCPUs each fork is counted as when placing (default: 1; forks of one world are mostly idle). |

| <span id="cua-sandbox-bake--tier"></span>`--tier` |  | string |  | Tier for an alias IMAGE (`docker` for a Docker-ready Linux VM). |

### `cua cache prune`

### `cua cache config`

Show or set the cache settings (`$CUA_HOME/cache.json`; the CUA_CACHE_BUDGET, CUA_DISK_MIN_FREE, CUA_DISK_WARN_FREE and CUA_ORPHAN_REAP_MINUTES environment variables win).

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Success. |
| `1` | Failure, or `cua do` reported an error. |
| `2` | Invalid argument, or an ambiguous sandbox name (qualify it: `local:NAME`). |
| `3` | Not found: sandbox, window, skill or image (or an image not published yet). |
| `4` | Not supported, or not configured (for example no provider credentials). |
| `5` | No cua-spacesd answered, or a transport failure. |
| `6` | Unauthenticated or permission denied (by Cua or your cloud account). |
| `7` | Not enough free disk space (see `cua cache`). |
| `8` | No room on the machine: its VMs are at their memory or CPU limit, or it is low on memory. |
| `130` | Cancelled (Ctrl-C during a create): what it made was removed. |
