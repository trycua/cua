## Spaces tools

The Spaces contract: register, claim and release Spaces, run commands, move files, stream, run agents and teleport.

These tools are the [Spaces contract](/spaces/reference), with the same names and schemas on every surface. Each links to its entry there (parameters, result, errors, providers, metering); `cua mcp` gates each one behind the permission `spaces:<tool>`.

### `sandbox_create`

Create a sandbox from any image. `on` says where (local, the default unless the user configured another with `cua config set default.on`), `kind` what (auto, container, vm) and `runtime` which engine (auto, or gvisor, runc, qemu, lume); an impossible combination fails and lists the valid values. To browse the web, pass browser=true (and optionally url): it starts the canonical Linux image, registers it as a Space, launches Chromium with a throwaway profile inside it and returns the space, session, target_id and tab_id to pass to call_tool with the in-sandbox browser tools (browser_navigate, get_browser_state, browser_click, browser_type). Pass command, env and services to run a server in it, for example an MCP server: services &#123;"mcp": 8765&#125;. Without browser=true it does not register a Space: to reach its MCP server with list_tools/call_tool (service="mcp"), use create_space instead (same arguments), or add this one with add_space (address local:&lt;name&gt;).

Permission: `sandbox:create`.

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| <span id="sandbox_create--browser"></span>`browser` | `boolean` |  | Start a browser in it, ready for the cua-driver browser tools (default image: the canonical Linux image). |
| <span id="sandbox_create--command"></span>`command` | `string[]` |  | Entrypoint override (argv), for example ["python", "-m", "my_mcp"]. |
| <span id="sandbox_create--env"></span>`env` | `object` |  | Environment variables (string values). |
| <span id="sandbox_create--image"></span>`image` | `string` |  | Image reference, any registry (overrides os_type). |
| <span id="sandbox_create--kind"></span>`kind` | `"auto" \| "container" \| "vm"` |  | What kind of machine: auto (default; from the image), container or vm. |
| <span id="sandbox_create--name"></span>`name` | `string` |  | Sandbox name. |

## Teleport tools

### `teleport_browser_session`

Teleport the user's signed-in session for specific sites (for example github.com) from their Firefox or Chrome into a sandbox, through the Cua Keyvault. Name each site: nothing is selected by default and there is no all-sessions option. The first call moves nothing: it files a Keyvault request and returns consent_required, a summary and a request_id. Show the summary to the user; they approve it in Cua (Touch ID or password). Then call again with the request_id to move exactly those sites. Use it only when the user asks to browse as themselves.

Permission: `teleport:browser`.

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| <span id="teleport_browser_session--browser"></span>`browser` | `"firefox" \| "chrome"` | required | firefox or chrome (chromium, brave and edge profiles use chrome). |
| <span id="teleport_browser_session--duration_minutes"></span>`duration_minutes` | `integer` |  | How long the sandbox may keep them (default 15, at most 1440). |
| <span id="teleport_browser_session--name"></span>`name` | `string` | required | Sandbox ref (local:&lt;name&gt;, direct:&lt;host:port&gt;) or a name unique across locations. |
| <span id="teleport_browser_session--reason"></span>`reason` | `string` |  | Why, in a few words; shown to the user as unverified. |
| <span id="teleport_browser_session--request_id"></span>`request_id` | `string` |  | The request_id from the first call, after the user approved it in Cua. |
| <span id="teleport_browser_session--sites"></span>`sites` | `string[]` | required | The exact sites to teleport, for example ["github.com"]. |

**Example arguments**

```json
{"name":"<name>","browser":"firefox","sites":["<site>"]}
```

## Permissions

Tools are gated by `--permissions` (or `CUA_MCP_PERMISSIONS`), a comma-separated list of permissions and groups; the default is `all`. Each group has an `all` and a `readonly` form (`sandbox:readonly`); each tool lists its own permission.

| Group | Grants | `:readonly` grants |
| --- | --- | --- |
| `computer:all` | 12 permissions | `computer:screenshot` |
| `images:all` | `images:list` | `images:list` |
| `sandbox:all` | 10 permissions | `sandbox:list`, `sandbox:get` |
| `skills:all` | `skills:list`, `skills:read`, `skills:record`, `skills:delete` | `skills:list`, `skills:read` |
| `spaces:all` | 86 permissions | 28 permissions |
| `teleport:all` | `teleport:browser` | none |
