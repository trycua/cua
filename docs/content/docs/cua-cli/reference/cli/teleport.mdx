## `cua teleport manifest`

## `cua teleport push`

Teleport an app session into a sandbox.

```text output
cua teleport push [OPTIONS] --app <APP>
```

| Flag | Short | Type | Default | Env var | Description |
| --- | --- | --- | --- | --- | --- |
| <span id="cua-teleport-push--app"></span>`--app` |  | string | required |  | App: a bundle id or app name ("com.google.Chrome", "Slack", "claude-code"). |
| <span id="cua-teleport-push--scope"></span>`--scope` |  | string | `full` |  | `tabs` (open tabs and session state) or `full` (the whole profile). |
| <span id="cua-teleport-push--profile"></span>`--profile` |  | string |  |  | Chrome profile to capture: a name ("Profile 1") or a path. |
| <span id="cua-teleport-push--display-name"></span>`--display-name` |  | string |  |  | Display name for the app (UI only). |
| <span id="cua-teleport-push--sandbox"></span>`--sandbox` | `-s` | string |  |  | Destination sandbox (name). |
| <span id="cua-teleport-push--url"></span>`--url` |  | string |  |  | Destination cua-spacesd URL instead of a sandbox. |
| <span id="cua-teleport-push--token"></span>`--token` |  | string |  | `CUA_ENV_TOKEN` | Token for `--url`. |
| <span id="cua-teleport-push--include"></span>`--include` |  | string |  |  | Send exactly this manifest item (repeatable; see `manifest`). Default: the provider's default selection, which leaves credentials-heavy or bulky items (cookies, transcripts) out unless named here. |
| <span id="cua-teleport-push--all"></span>`--all` |  | boolean | `false` |  | Send every item the scope offers. |
| <span id="cua-teleport-push--no-launch"></span>`--no-launch` |  | boolean | `false` |  | Do not launch the app in the sandbox after importing. |
| <span id="cua-teleport-push--progress"></span>`--progress` |  | boolean | `false` |  | Print `progress <sent> <total>` lines while uploading. |
| <span id="cua-teleport-push--relay-plaintext-ack"></span>`--relay-plaintext-ack` |  | boolean | `false` |  | Send over a `relay:` destination even though this Space's image predates end-to-end sealing (S1): without this, such a send refuses before reading or uploading anything. Set it only after you understand that relay.cua.ai (or a self-hosted cua-relay) could read this delivery in the clear; local and direct destinations are unaffected either way. |

**Examples**

```bash test="cli-shape" id="ref-cua-teleport-push"
# Chrome's open tabs into the sandbox dev
cua teleport push --app com.google.Chrome --scope tabs --sandbox dev

# The whole Slack profile, every item
cua teleport push --app Slack --sandbox dev --all
```

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Success. |
| `1` | Failure, or `cua do` reported an error. |
| `2` | Invalid argument, or an ambiguous sandbox name (qualify it: `local:NAME`, `cloud:NAME`). |
| `3` | Not found: sandbox, window, skill or image (or an image not published yet). |
| `4` | Not supported, or not configured (for example no Fleet credentials). |
| `5` | No cua-spacesd answered, or a transport failure. |
| `6` | Unauthenticated or permission denied (by Cua, Fleet or your cloud account). |
| `7` | Not enough free disk space (see `cua cache`). |
| `130` | Cancelled (Ctrl-C during a create): what it made was removed. |
