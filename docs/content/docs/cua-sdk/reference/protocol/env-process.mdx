## ProcessService

`cua.env.v1.ProcessService`

Runs and supervises guest processes.

Processes are detached from the RPC that started them: a client disconnect
does not kill the process unless `StartProcessRequest.kill_on_disconnect`
is set. Output goes to a bounded scrollback ring so a client can reattach
with `ConnectProcess` (by pid or tag) and replay recent output. After a
process exits, its exit status and scrollback stay in a retention cache
(at least 10 minutes and the most recent 256 processes) so a late
`ConnectProcess` still observes the `ProcessEnd`.

Output offsets: every byte a process writes to stdout, stderr or its PTY
is numbered in one combined, monotonically increasing byte space starting
at 0. `ProcessData.offset` is the offset of the chunk's first byte, which
lets a reconnecting client drop output it has already seen.

### ProcessService.StartProcess

`/cua.env.v1.ProcessService/StartProcess`, server stream: [`StartProcessRequest`](#startprocessrequest) to [`StartProcessResponse`](#startprocessresponse).

Starts a process and streams its lifecycle and output. The first event is
always `ProcessStart`, the last is `ProcessEnd` (unless the client
disconnects first). Cancelling this RPC detaches; it does not signal the
process unless `kill_on_disconnect` is set.

### ProcessService.ConnectProcess

`/cua.env.v1.ProcessService/ConnectProcess`, server stream: [`ConnectProcessRequest`](#connectprocessrequest) to [`ConnectProcessResponse`](#connectprocessresponse).

Attaches to a running or recently exited process. The stream begins with
`ProcessStart`, then up to `replay_bytes` of scrollback, then live
output, then `ProcessEnd`.

### ProcessService.ListProcesses

`/cua.env.v1.ProcessService/ListProcesses`, unary: [`ListProcessesRequest`](#listprocessesrequest) to [`ListProcessesResponse`](#listprocessesresponse).

Lists managed processes.

### ProcessService.SendInput

`/cua.env.v1.ProcessService/SendInput`, unary: [`SendInputRequest`](#sendinputrequest) to [`SendInputResponse`](#sendinputresponse).

Writes one chunk to a process's stdin or PTY. The unary, gRPC-Web-safe
equivalent of `StreamInput`. Chunks may carry sequence numbers for
exactly-once, in-order delivery across retries.

### ProcessService.StreamInput

`/cua.env.v1.ProcessService/StreamInput`, client stream: [`StreamInputRequest`](#streaminputrequest) to [`StreamInputResponse`](#streaminputresponse).

Streams stdin or PTY input. Native gRPC only; gRPC-Web clients use
`SendInput`. The first message must set `process`.

<Callout type="info">gRPC-Web cannot carry client streams. Over gRPC-Web, call the unary [`SendInput`](#processservicesendinput) instead (`/cua.env.v1.ProcessService/SendInput`).</Callout>

`/cua.env.v1.ProcessService/CloseStdin`, unary: [`CloseStdinRequest`](#closestdinrequest) to [`CloseStdinResponse`](#closestdinresponse).
