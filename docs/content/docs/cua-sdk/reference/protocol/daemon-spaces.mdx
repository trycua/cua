Spaces through the local `cua daemon` (create, list, power, delete, and the computers that provide Spaces), batch runs on your computers (`PoolRequest`), the daemon identity (`GetInfo`) and the loopback media bridge for webviews.

## SpaceService

`cua.daemon.v1.SpaceService`

Spaces: sandboxes with Spaces features (cua-spacesd, streams, agents,
teleport) that the user works in interactively. The daemon hosts one
`cua_spaces::Spaces` runtime: the registry in `~/.cua/spaces.json`
(tokens in the 0600 `spaces-credentials.json`), Space creation in every
location, hotspots, and the Spaces MCP server (`CallSpaceTool`,
`cua daemon mcp`, `/mcp`).

Verbs: `CreateSpace` / `DeleteSpace` create and delete the sandbox;
`AddSpace` / `RemoveSpace` register an existing machine and forget it
without touching it.

### SpaceService.CreateSpaceStream

`/cua.daemon.v1.SpaceService/CreateSpaceStream`, server stream: [`CreateSpaceStreamRequest`](#createspacestreamrequest) to [`CreateSpaceStreamResponse`](#createspacestreamresponse).

`CreateSpace`, streaming what the create is doing: progress events

### SpaceService.CancelCreateSpace

`/cua.daemon.v1.SpaceService/CancelCreateSpace`, unary: [`CancelCreateSpaceRequest`](#cancelcreatespacerequest) to [`CancelCreateSpaceResponse`](#cancelcreatespaceresponse).

Cancels a create that is still running, found by the caller's
`create_id`, the id the Space will have (every progress event carries
it in `space`) or its name: the work in flight stops (an image
download, a boot, a relay registration) and what the create
made is removed (its VM or container and disks, its
relay machine, its registry entry). Nothing that existed before is
touched; finished image downloads stay cached so the next create
resumes. Returns once the clean-up is done; the create itself ends with
DAEMON_ERROR_REASON_CANCELLED. Idempotent, and works for a create
another process runs or one a daemon restart cut off.

### SpaceService.PoolRequest

`/cua.daemon.v1.SpaceService/PoolRequest`, unary: [`PoolRequestRequest`](#poolrequestrequest) to [`PoolRequestResponse`](#poolrequestresponse).

Batch runs on your machines (`cua sb run`): one request to this
machine's own coordinator (`target` `local`: work that never leaves

them (`pool`). `method`, the JSON params and the JSON answer are the

### SpaceService.GetResources

`/cua.daemon.v1.SpaceService/GetResources`, unary: [`GetResourcesRequest`](/cua-sdk/reference/protocol/daemon-resources#getresourcesrequest) to [`GetResourcesResponse`](/cua-sdk/reference/protocol/daemon-resources#getresourcesresponse).

What this computer, its extra Spaces and your other computers use now:
processor, memory and disk, as one snapshot. The daemon's single
sampler measures it; a snapshot a few seconds old is returned as it is.
With `visible`, the call also says a window shows the numbers for the
next 30 seconds, so the sampler runs every 10 seconds (every 5 minutes
otherwise). Numbers only: no names, paths or processes.

### SpaceService.WatchResources

`/cua.daemon.v1.SpaceService/WatchResources`, server stream: [`WatchResourcesRequest`](/cua-sdk/reference/protocol/daemon-resources#watchresourcesrequest) to [`WatchResourcesResponse`](/cua-sdk/reference/protocol/daemon-resources#watchresourcesresponse).

The same numbers as a stream: one snapshot first, then an update with
only the entries that changed by more than 1 point or 256 MB, and a
`low_disk` event whenever the free-disk warning level changes
(including back to `ok`). A hidden watcher (`visible` false) is
sampled every 5 minutes and still hears `low_disk`, for the menu bar.
Cancel the stream to stop; call again with the other `visible` to
switch.

### SpaceService.WatchSpaces

`/cua.daemon.v1.SpaceService/WatchSpaces`, server stream: [`WatchSpacesRequest`](#watchspacesrequest) to [`WatchSpacesResponse`](#watchspacesresponse).

Says when the Space list changed, so a client reads it again
(`ListSpaces`) when something happened instead of on a timer: one
message at once (the generation now), then one per change. This
computer's Spaces are announced within a second; your other computers
on the mesh within about a second of connecting or going away (the mesh
coordinator pushes it); computers not on the mesh within 10 seconds.
Cancel the stream to stop.
