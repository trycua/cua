Control trajectory recording on a running daemon.

Recording state lives in the required daemon and survives client reconnects.

```text output
cua-driver recording [OPTIONS] [COMMAND]
```

Without a subcommand, runs `cua-driver recording status`.

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| <span id="cua-driver-recording--socket"></span>`--socket` | string |  | Override the daemon socket or named-pipe path. |

## `cua-driver recording render`

Render a recorded trajectory directory to an MP4.

This pure file-to-file path does not require a running daemon.

```text output
cua-driver recording render [OPTIONS] <input-dir> <out-mp4>
```

| Argument | Type | Default | Description |
| --- | --- | --- | --- |
| `<input-dir>` | path | required | Trajectory directory containing recorded turn folders. |
| `<out-mp4>` | path | required | Output MP4 path. |

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| <span id="cua-driver-recording-render--scale"></span>`--scale` | number |  | Scale factor for rendered frames. |
| <span id="cua-driver-recording-render--no-zoom"></span>`--no-zoom` | boolean | `false` | Disable cursor/action zoom effects in the rendered video. |

**Examples**

```bash test="cli-shape" id="ref-cua-driver-recording-render"
# Render a recorded trajectory to MP4
cua-driver recording render ~/cua-trajectories/demo1 demo1.mp4
```
