---
title: Child Spaces
description: 'Let a Space make Spaces of its own: an agent inside it creates, uses and deletes children, without your account and without reaching anything else.'
---

import { Tabs, Tab } from 'fumadocs-ui/components/tabs';

A Space can make Spaces of its own. An agent working inside it can fork 32
copies to run a benchmark, start a fresh machine to test a build, or try a
change on a clean desktop, then delete them. These are its children: they
belong to it, and it can reach nothing else.

An agent run turns this on for its Space by itself. For any other Space you
turn it on yourself.

## Turn it on

<Tabs items={['CLI', 'SDK']}>
  <Tab value="CLI">
    ```bash test="cli-shape" id="children-on"
    cua spaces create linux --name studio --children
    cua spaces children studio on
    cua spaces children studio off
    ```
  </Tab>
  <Tab value="SDK">
    ```python skip="no-runner"
    import cua

    spaces = cua.auto().spaces()
    await spaces.create(cua.SpaceCreateOptions(name="studio", children=True))
    await spaces.set_children("studio", False)
    ```
  </Tab>
</Tabs>

Off ends the Space's right to make children at once. Children it already
made keep running until they are deleted or their time runs out.

## Inside the Space

Nothing to set up. The same commands and tools work, and every Space they
make is a child of this one:

```bash skip="no-runner"
cua spaces create linux --name worker
cua spaces ls
cua sb exec worker -- make test
cua spaces rm worker
```

An agent gets the same as tools in its Space's own MCP server:
`create_space`, `fork_space`, `list_spaces`, `space_bash`, `stop_space`,
`start_space` and `delete_space`. Code that uses the SDK
(`cua.auto()`) works too.

## What a child gets

- **This machine.** A child runs on the same machine as its parent.
- **No wider network.** It keeps its parent's egress rules. A request for
  wider ones is refused.
- **No longer life.** It ends when its parent would, and after 4 hours at
  most unless you give it longer.
- **Limited depth.** A child may make children of its own, two levels
  below the Space you made. Deeper requests are refused.

## What a Space can't do

The channel a Space uses answers for its own children and nothing else.

- **Other Spaces.** Your other Spaces, its parent and its siblings look
  the same as a Space that does not exist.
- **Your account.** It holds no account sign-in, cloud link or key, so it
  can't share, connect clouds or reach your other machines.
- **A copied capability.** The capability it holds works only on its own
  channel. A copy taken from a snapshot, a fork or another Space is
  refused.

The channel is not a network port. The Space's own cua-spacesd keeps it on
the Space's loopback and hands each connection to this machine's cua daemon
over the connection the daemon opened. The daemon knows which Space is
asking from the connection, never from what the Space says.
